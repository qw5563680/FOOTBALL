Implemented

1. stats_link.py + stats_match_identity.py
   Load existing result_source_links through its current-snapshot validator. Build
   components from the complete graph, including scheduled and out-of-window rows.
   Multiple direct candidates collapse only when every candidate belongs to one
   proven component and sources remain unique. New indices choose jc > fd > fdorg
   > apif. A valid old index retains its original component member and all fields.
   Reverse/shared candidates and unproved third candidates still reject. Claims
   and batch uniqueness cover the entire component, including members outside the
   incoming fixture's window. A retained APIF ID cannot authorize another raw
   provider fixture ID. Existing FD/FDORG same-kickoff preference remains intact.
   Added audit reason verified_same_match, with the candidate IDs and actual target.

2. stats_schedule.py
   A sold JC grants pregame eligibility to an existing index through a currently
   validated proof component, without writing any counterpart pointer. Competing
   index fixture IDs in one component and contradictory retained APIF IDs cannot
   obtain new eligibility. Original statuses, 30–60 minute window, missed-window
   rules, request key, cursor behavior, and legacy sale links remain unchanged.
   Operational scheduler accepts proof verified at or before now; pregame feature
   consumers below require strictly earlier proof, as requested by root.

3. result_source_groups.py + experiments/history.py + parallel.py
   The new pure helper receives already validated links, forms components with
   verified_utc < as_of, and retains source-uniqueness checks when adding them to
   the pre-existing exact/pointer grouping. The daily parallel host passes its
   explicit model cutoff to unified_history. Completed label rows retain the
   original source ranking and latest/earliest kickoff semantics.
   Crucially, a returned feature builder re-resolves its proof view at EACH build
   call's cutoff; the model-wide cutoff is never used to borrow a later proof for
   an earlier historical feature. Views are cached by eligible proof tuples.
   Scheduled nodes may establish identities but never become completed histories.

4. features/injuries.py
   Each public build creates a read-only identity view from proofs strictly before
   min(as_of, earliest aligned kickoff). If alignment moves the cutoff earlier,
   eligibility is rechecked at that earlier time. The view then performs the same
   index, previous-match, snapshot and lineup calculations as before. Two indices
   in a proven component remain ambiguous. Proofs never get the backfill-replay
   exception that technical observations already have.

5. experiments/command.py
   Post-fit market comparison additionally finds JC through current proven links
   strictly before that row's feature cutoff and both endpoints' kickoff. The
   original unaligned identity view is used to validate proof clock offsets.
   This only repairs comparison lookup; no odds are added to feature/model inputs.
