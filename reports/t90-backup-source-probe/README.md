## 正式采集机验收

合并后由 DeepSeek 在 `main` 手动运行 **Football cloud feeds**，`operation` 选 `probe`，`options` 填 `{"probe_kind":"backup-sources"}`。独立探测附件名为 `backup-sources-<run>-<attempt>`。[工作流](https://github.com/qw5563680/FOOTBALL/actions/workflows/football-feeds.yml)

- 同一品牌最多尝试 3 个公开 HTML 页面。每个涉及的来源域先读取自己的 `robots.txt`。按规则的访问时段和频率执行，连续请求至少间隔 3 秒。
- `README.md` 汇总每种用途的结论。`probe.json` 记录各请求的 URL、时间、HTTP 状态、robots 判定、原始响应 SHA-256 和分类原因。`samples/` 保存供复核的裁剪证据，以赛程字段和解析依据为限。`SHA256SUMS` 用于核对附件文件，原始响应的哈希来自本次抓取时的响应字节。
- 用同一地址多次读取的结果判断短时稳定性。只有一次请求时记录观察次数，暂不判定稳定。核对样本中有明确主客和开球时刻的静态比赛行，并记录每项字段的实测覆盖。
- DeepSeek 回填 Actions 运行链接、附件、哈希及每个候选在相应用途下的「可用／不可用／需所有者决定」。Claude 对照原始证据及裁剪样本验收，再将核实结果同步到数据来源文档。[数据来源](../../docs/DATA_SOURCES.md#t90-新球体育雷速体育和澳客竞彩探测)
