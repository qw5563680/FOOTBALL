## 5. 最小修复方案与试验边界

### 第一层：已有明确 fd counterpart（184 场，零体育请求）

后续修改 `stats_storage.ingest_fd`：将唯一、同联赛、时间一致的既有 jc.counterpart 查找从 `daily` 专用扩大到历史原件回放；`store_rows` 已允许这种附着。保持 `daily=False`、`availability_basis=backfilled`、`available_utc=null`、真实原件 captured_utc，不能为了导入假装日常新抓。

试验在隔离 DB 上把这 184 场的原件解析结果交给当前 `store_rows(daily=False)`，新增 **2,944 行**（每场 16 技术字段，含真实 null）；原比赛、球队、赛果和 counterpart 不变。四格齐全由 0 变 **3 场**：jc:2042558、jc:2042567、jc:2042601。剩余 18 场仍不齐，不能承诺只改 daily 分支就恢复全部。

两个指定例子：

- jc:2041466，圣旺红星—梅斯，counterpart=`fd:F2:20260914:red-star:metz`，库内无 fd 实体；S5 原件第 55 行 HST=7、AST=1，11-04 14:04:28.796121Z 已捕获；stats_ingest_audit 明记“未找到唯一且时间一致的既有 fd 行”。
- jc:2041926，第戎—梅斯，counterpart=`fd:F2:20261012:dijon:metz`，库内无 fd 实体；S5 第 73 行 HST=7、AST=4，同一捕获时间及拒绝理由。
- 在另一隔离副本实际重跑原 `ingest_fd(daily=False)`，F2/2627 返回 inserted=0、rejected=16，两个指定 jc ID 仍为0条fd统计；生产解析器能原样解析这四个值。归档分片/恢复库无对应 fd 统计；`unified_history` 不会凭空创建不存在 fd 实体的统计，因此 `_value` 返回 not_provided。没有源缺项、未来捕获或恢复丢失。

### 第二层：26 场有原件但缺可用 fd 附着（零体育请求，需后续正式设计）

25 场 jc counterpart 已给 fdorg；另 1 场兹沃勒—海牙（jc:2042418）为空。用**已批准的精确别名→现有球队 ID**、同联赛同向主客、开球±3小时双向唯一、原件哈希定位，共核实 26 个唯一原件候选，不做相似名推断。新增方案应记录独立的 fd 统计关联证据，并同步 `stats_storage.store_rows`、`stats_archive.check_stats` 的合法性验证；**不要覆盖生产中现有 fdorg counterpart，不要新建重复比赛**。也可由后续设计选择经过审查的 fd/jc 多来源链接表达，不能只放宽校验而不留证据。

隔离因果试验为了通过现有 writer 的硬约束，仅在临时副本中暂时把这 26 个 counterpart 指向已验证的 fd 外部编号，再用原 parser/store_rows 加 **416 行**；原值及试验替换逐条记录在 `counterfactual.json → trial_links`。该替换仅用来证明关联阻塞，**不是可直接用于生产的修复方案**。21 场所选历史 ID 列表完全不变。合并两层后，共 **16/21** 目标四格齐全；没有重新拟合或发布概率，不等于 16 场已经有有效预测，更不证明准确率提升。

### 重放、幂等与调度

后续修复应定向回放这 9 份已归档 2627 CSV，不必为210场重新请求接口。`stats_batch` 将“文件成功解析但有拒绝行”记 ok，`stats_schedule.resume_units` 跳过 ok；只修函数再原样 resume 可能不会处理任何旧拒绝，需明确一次性离线原件重放入口和拒绝清单范围。已有 ingested 原件幂等规则保留，不删除统计、不改旧时钟。

当前 daily fd 通道仅复用周一 early 已下载的文件。本次是周五 UTC late，日志“Preserve captured statistics…”步骤 skipped，晚班 API 技术采集不会自动补 fd 射正。等待下一周一也不自动解决26场附着缺口和窗口不足；应先修入库和关联，再安排受控验收。
