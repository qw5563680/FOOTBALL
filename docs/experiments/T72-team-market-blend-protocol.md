## 假设与固定数据

分别检验融合能否改善球队模型，以及融合能否胜过直接看市场。以三分类 Log Loss 为主指标。回溯使用出版方收盘价，市场比出单时拥有更多信息，可能高估融合效果。回溯只给初始权重，不用于认定前瞻表现。

- 数据固定为 [归档提交 a87f2757](https://github.com/qw5563680/FOOTBALL/tree/a87f27574cafb3297c7e68ca0363679cb471a203)，`feed_manifest.json` 的 SHA-256 为 `0352dfa9ba9416e4b51ee47bceda6952e841138877538c45048077ca84cfbd40`。从这份归档恢复独立数据库，复核输入与副本哈希。归档清单有 100,969 条收盘价记录，这个数是库存，实际共同样本量以运行报告为准。
- 球队模型沿用基点 `8b7dd50feaaf83dac939e55dc433e723a993d490` 已有的 Dixon–Coles 周滚动回测和原七联赛来源 `fd,jc`。联赛固定为英超、西甲、德甲、意甲、法甲、葡超、巴甲。参数 `data/model/params.json` 的 SHA-256 为 `12cafa6c60adc19a6629da74f6cc40d360cb8c34ef3997da1f26a01099dfa888`。
- 原回测用开球所在 UTC 周与赛季边界切折，训练截点为折开始前一微秒，使用该截点时按现有可知时间规则可用的累计历史。参数只取为该季预先选定的 `evaluation_windows` 条目，现有缺省值是 90 天且平局校准关闭。已归档的每折训练场数、训练结果可知时间和 assumed 比例一并披露。静态库沿用原 FD 的 assumed 时间，不能用来证明生产在那个时间已收到赛果。
- 球队模型逐场输出后，以相同比赛 ID 配对该场的收盘价。沿用 T15 的完整胜平负收盘价优先级 B365、PS、Avg，三项均须有限且大于 1，取倒数后去水归一。找不到同一 ID 的合格价格就记缺失。逐场指标使用 90 分钟含补时赛果，并要求赛果的可知时间严格晚于开球且早于所属阶段终点。

## 事前切分与选权重

边界含首不含尾。北京时间是下表 UTC 边界当天 08:00。

| 阶段 | UTC 起点 | UTC 终点 | 用途 |
| --- | --- | --- | --- |
| 训练 | 2024-07-01 00:00 | 2025-07-01 00:00 | 选择一次初始市场权重 |
| 验证 | 2025-07-01 00:00 | 2026-01-01 00:00 | 按固定权重计算一次 |
| 留出 | 2026-01-01 00:00 | 2026-07-01 00:00 | 按同一权重计算一次 |

融合概率为 `normalize(p_TEAM^(1-w) × p_MARKET^w)`。胜、平、负按 `h/d/a` 顺序固定。两个输入都须为合法胜平负分布。训练段共同样本上，网格为 `0.00, 0.01, …, 1.00`，取 Log Loss 最小的权重，数值同分时取较小权重。没有共同训练样本则停在选权重之前。先把所选权重和网格成绩写进 `weight-selection.json`，再依次计算验证段和留出段。验证或留出结果只作报告。

每段先记录目标总数、共同样本数及排除原因，再在共同样本上分别报告球队、收盘、融合三列的 Log Loss、三类平方误差之和的 Brier 和首选命中率。对数损失下界为 `1e-15`，最高概率并列时每个首选分得 `1/k`，真实结果命中其中一项才得分。分母按冻结比赛 ID 配对。标签不可用、缺球队预测、缺合格收盘价逐条保留。全量逐场 JSONL 不进入代码分支。

## 前瞻冻结、比较与检查点

初始权重须在回溯报告、阶段、共同样本量及成绩提交后独立批准。配置 `data/model/team-market-blend.json` 保存生效 UTC、权重版本、市场权重、协议 SHA-256、固定归档 SHA、回溯报告 SHA-256 和三个阶段结束 UTC。正式冻结从合并后且获批版本生效的首批开始。生效前的批次和缺有效配置、球队预测或合格市场快照的场次保留未生成原因。

单场融合只使用同一批准正式批次里已冻结的球队胜平负和该批截点不晚于 `as_of_utc` 的 T71 合格市场快照。原快照须在开球前可知，使用档案中记录的实际采集时刻与快照标识。前瞻比较须核验该批在赛前发布，比赛身份、有效赛果和三列配对一致。收盘价另作赛后对照，只有其自身的覆盖、分母及成绩。旧手动线性融合、基准预测和既有技术实验不计入本协议。

两个差值均按同一比赛 ID 配对，按开球的 UTC 周（周一开始）成块，自助重采样 2,000 次，
固定随机种子 `3301`，取第 2.5 和 97.5 百分位。前瞻 Log Loss 用实际类别的 `-log(p)`，
实际类别概率为零时记录无穷大。区间若因不足两周或非有限值而无法成立，则继续标未能判断。
首次 300 场检查点按赛果可知时间、比赛开球时间和 ID 排序冻结，旧检查点在后续运行保留。

前瞻共同样本还没到 200 场时，只报告三列覆盖、指标与配对区间。样本达到 200 场后，融合减球队的 Log Loss 差值 95% 区间上界小于 0，才报告「市场信息帮到了球队模型」；融合减市场的区间上界小于 0，才报告「融合比直接看市场有额外好处」。其他情况照实报告证据不足。样本满 300 场时，融合减球队区间上界不小于 0，或融合减市场区间下界大于 0，标记达到任务单关停条件。融合与市场未发现显著差异时，只报告未发现额外好处，由所有者决定是否保留。

每累计 200 场前瞻共同样本才可复估。复估使用截至该检查点已有真实比分的冻结成对样本，沿用训练段网格、主指标和并列规则。无有据版本变更时继续用旧权重。批准后的新权重从之后的批次生效，版本与证据独立，历史版本及其成绩保持原样。融合独立记分，正式球队模型、T94 基准、爆冷、任九、14 场复式、虚拟账户及纸面串关保持各自原有入口。BET 禁用。

满 200 场时，在冻结归档的副本上用 `python -m zucai.market_blend_reestimate` 生成第一份提案。其后每次提供上一份提案，新增 200 场才可生成下一份。按赛果可知 UTC、开球 UTC、比赛 ID 固定前缀。提案包含逐场记录编号、计分文件和上份提案的哈希；同一输出路径只写一次。收盘价不参与复估。

提案经独立审查和所有者批准后，把前一版完整配置放入 `previous`，在新版 `prospective` 保存 `checkpoint`、`as_of_utc`、`score_sha256`、提案 `report_sha256` 及 `previous_weight_version`。新区间的 `effective_from_utc` 必须晚于复估截点。达到生效时刻前仍读取旧版，旧版证据哈希保持一致。提案命令不写生效配置。

## 审查后离线执行

```bash
python -m zucai.market_blend_backtest --archive <固定归档副本> --out <新的报告目录> --review-url <Claude-Code-审查链接>
```

该命令只读固定归档，恢复临时库，向指定新目录写入 `weight-selection.json`、三段逐场 JSONL 及 `report.json`。报告记录原件、参数、数据库、协议及逐段文件的 SHA-256；无网络请求。正式验收报告只提交 README 和哈希清单，逐场证据放已授权的项目归档或 Release，示例和离线合成测试不能冒充历史回溯成绩。
