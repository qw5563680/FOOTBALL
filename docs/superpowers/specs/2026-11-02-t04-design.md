# T04 赛前球队特征工程

用户要求继续直接开发下一功能；现有T01–T07中T04尚未实现，本次补齐该既有任务。使用Python/pandas与SQLite，不训练或替换模型，不修改既有预测，不新增网页或定时任务。

## Approaches
选择从已有规范化数据库提取带可知时间的特征。仅按开球排序rolling会让晚采集/晚公布的赛果穿越截点；接入外部伤停/xG增加未授权数据依赖。采用严格逐场截点过滤和明确字段白名单，为后续模型实验提供可复核输入。

## 截点和范围
- `build_features(session, match_ids=None, as_of=None, *, strict_availability=False) -> DataFrame`。as_of为带时区时间，默认真实当前UTC；拒绝未来as_of和无时区输入。目标列表None表示全库，空列表返回有固定schema的空表；重复/未知ID报错。
- 每场有效截点=`min(as_of, kickoff_utc)`。历史比赛必须不同于目标、状态finished、开球和赛果available_utc都严格早于截点，且available不早于历史开球。未知可知时间/无效依据排除并计数。
- `available_source`沿用项目约定：有时间但旧标记NULL视为captured；assumed默认可用但逐窗口披露数量。strict_availability排除assumed。不能把固定延时假设称为真实采集证明。
- 近况、主客场和交锋只取同来源同联赛，跨赛季沿用已有数据并明确披露；不会合并不同来源的同一场。休息天数按同来源所有赛事最近已知完赛计算，以目标开球减该场开球，名称含义为“距最近已知完赛的间隔”，并非已核实的真实赛程休息期。
- 不读取目标赛果，不生成目标标签，不使用目标赛后xG、赛季最终排名或后于截点的赔率。现有数据库不是全量历史版本库，重建不能声称为当时冻结的未见验证。

## 数值与证据
- 主客各自last5/last10：进球、失球、3/1/0积分的普通均值和90天半衰期归一化加权均值。权重与`2^(-距截点天数/90)`成比例；用最新样本为数值基准防下溢，结果等价。
- 主队home5、客队away5：同样六项均值。窗口不足按实际有效场数算，空窗口NaN；每窗记录n、assumed_n、已使用比赛ID与可知时间。
- 最近3次交锋按目标主队视角算主胜/平/客胜率及双方平均进球；元数据保留由近到远的3/1/0结果和证据。无交锋为NaN。
- 完整had市场只选择同一时刻h/d/a、line=0、价格有限且>1，快照严格早于有效截点。使用最新合格完整快照，逆数比例归一化。`market_line`为该had快照的0，无报价则NaN；不会混入hhad让球线。全部`market_`列禁止进入MODEL_FEATURE_COLUMNS白名单。
- 元数据以meta_前缀和DataFrame.attrs隔离：身份/截点/原始状态、样本数量、来源及使用证据、提取时刻与版本。不做概率、校准或准确性结论。

## CLI与冻结导出
`zucai features build [--db] [--match-id ID 可重复] [--as-of ISO] [--strict-availability] [--out data/features.parquet]`。
只读已有数据库，不创建或迁移输入库。默认Parquet；使用可选features依赖pyarrow，dev安装包含它，正式环境不安装。
排他创建features.parquet、features.metadata.json、features.manifest.json；已有任一文件即拒绝。失败只清理本次创建的文件。
metadata保存完整证据/列清单/缺失比例，manifest校验Parquet与metadata。模型特征白名单显式导出，当前Dixon–Coles不自动读取此表。
