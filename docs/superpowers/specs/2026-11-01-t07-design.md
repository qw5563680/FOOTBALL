# T07 14场胜负彩期次分析

用户要求直接开发下一功能，按既有任务单 T07 执行。沿用 Python CLI、SQLite 和 T06 冻结报告，不新增网站、任九优化、投注操作或自动任务。

## Approaches
选用已核实的 500 静态 HTML + 严格身份匹配 + T06 冻结模型概率。重新建立独立预测模型会重复 T05/T06；取页面平均概率会违反独立球队模型要求。以上是实现选择。

## 输入、存储和身份
`C500Sfc` 实现 Source，GB18030 解码当前/指定期号页面，仅读取期号、完整截止时间、14个序号、赛事、主客、开球和分析链接 fixture ID。忽略赔率、平均概率、赛后比分与排名。采集保留原字节/URL/真实UTC时刻/SHA256。
当前页2026-11-01实测期号26156，截止2026-11-02 22:00；历史26155的buyendtime为空，必须存null。旧sfc_issues截止列迁移为可空且保留旧记录/外键。
短开球日期以完整截止时间推断跨年；没有截止时以期号年份解释，并拒绝无法消歧的跨年历史期次。任何日期推断在报告披露。
严格检查期号、14行连续不重复、fixture ID不重复和页面身份。缺行或错误页整期拒绝，避免14场顺序错位。
优先通过已保存counterpart或公开500竞彩根页的fixture/体彩ID与主客球队ID对照已有match，再核对联赛和开球；无可靠ID对照才按已知队名/别名、相同主客、联赛与时刻匹配。仅接受真实核实的瑞典超/瑞超别名，多个候选不猜。查找只读，最后确需新增时才创建球队/独立c500记录，保留待匹配原因，不自动扩充简称别名。不得覆盖已有官方赛程/状态；同c500 ID身份冲突拒绝。同期期次重新抓取保留raw，拒绝较旧快照覆盖。期次存原始身份和ID对照URL/读取时间/SHA等证据，导出冻结报告后旧版不变。
没有完整截止的历史页面，遇1月或12月即要求补充完整年份，不以较短日期跨度证明年份可靠。

## 报告与组合
`zucai fetch sfc [--issue] [--db]` 抓取并存储；`zucai report sfc [--issue] --batch forecast.json [--max-lines 64] --out NEW_DIR` 复用经SHA校验的T06单批纯模型概率。无issue仅在数据库恰有一期时自动选择，多个期次要求明确指定。
逐场核对冻结预测和当前映射的ID、主客、联赛、来源和开球时间。只使用同批纯模型P2概率，不用混合或市场值；赛后生成、historical_replay明确区分；报告时间不改变原预测时间。缺预测、身份冲突或取消场次显示原因，14场不全不生成组合。
在每场选1/2/3项的完整笛卡尔复式结构下，用动态规划按精确注数保留最大覆盖概率状态，默认上限64（最大3^14）。每个选择数量使用概率最高的对应项。明确跨场独立近似、14/14覆盖，不能称中奖/盈利概率、奖金或正EV。P2/BET禁用；历史/已截止/截止未知都不能称可出票。最多给一个最优覆盖结构和逐场置信度顺序，不以10万次模拟作证。
冻结sfc.json、report.md、report.csv、manifest.json，输出目录排他创建；部分写入回滚仅清理自己创建的文件。包含完整期次原始身份、映射、来源哈希、引用forecast哈希/全部模型依据和原概率，不依赖本机模型文件路径。无网络重导出T06不受影响。
