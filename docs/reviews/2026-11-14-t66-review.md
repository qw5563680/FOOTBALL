## 发现的问题与处理

1. **任务单要修的导出失败**：已修，逐种情形核对。只有「空指针改为该关联自己的 fd 键」由拒绝变为通过；
   别的 fd 键、其他来源、原 fdorg 指针被替换、两场指向同一 fd 键仍被拒绝。真实原件重放时主干以线上同一错误失败，
   本 PR 导出成功、再恢复一致。
2. **补采成功后欧战模型训练失败（第一轮，必须修）。** 免费文件停更的两周里，付费接口已把这些比赛存成 apif 行；
   补采进来的 fd 行与它们是同一场，共 34 对完全相同（日职 9、美职 7、瑞超 7、挪超 7、芬超 4），
   另有 apif 一方球队未绑定的情形。fd 导入不处理 apif 行，两行并存，欧战池的重叠检查拒绝训练。
   这是主干原有的缺口，被停更掩盖。处理：`bf7c603` 在 fd 行入库时把确属同一场的 apif 行并到 fd 行，
   判定只用同联赛、三小时以内、同位置球队编号相同；apif 恰好一方未绑定时要求另一方同位置相同；候选须唯一。
   训练读取时重新核验每条关系。
3. **采集节奏的新规则在真实数据上不成立（第一轮，必须修）。** 回执只在状态为 complete 时写，而真实导入
   必有拒收与疑似重复，于是每一班都重采；全程无拒收时又会把采集日固定在补采那天。
   处理：成功按「全部文件完成、没有整联赛失败」判定；节奏按 UTC 自然周、锚定周一。
4. 建议修两条：删除工具留下的计划文件；核实月度 Release 附件上限并确认统计复用回到每周一次。均已处理。
