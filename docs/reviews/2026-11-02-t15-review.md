## 泄漏与边界核查（逐点）

- **选参语料物理隔离**：`rolling_origin` 用 `kickoff_utc < origin and available_utc < origin` 切出语料后再评估，
  S+1 的赛果和价格不可能进入候选打分。测试 `test_late_labels_at_season_cutoff_cannot_enter_selection` 直接篡改 S+1 比分验证。
- **折截点**：weekly 在周一 00:00 UTC 前 1 µs 冻结；跨季的一周按赛季边界再切，确保新季参数不在选择时刻之前生效。
  `fit` 要求 `kickoff < cutoff`、`available < cutoff`、`available > kickoff`，三者严格。
- **收盘价**：只读 `closing_odds` 中 `pool=had, basis=publisher_closing`，B365 > PS > Avg，三项均 > 1 且有限才用；
  仅在 `_summary` 生成对照列。`DixonColes.fit/predict` 的输入帧不含价格列也不读取。
- **校准**：`fit_draw_offset` 只接收训练折内模型平局概率、实际平局与时间衰减权重；梯度 `Σ w(σ(l+b) − y)` 单调，
  [-6, 6] 边界保证极端样本有限。预测时对角线乘 `exp(b)` 再归一化，与 logit 平移等价（测试证实非平局间比例不变）。
- **门槛**：`p2_gate` 要求 weekly、两完整季、无跳过、无不可知标签、`in_period == n`、合计 n ≥ 500、
  收盘配对 n ≥ 500 且与模型配对数一致、LL 增益 ≥ 0.05、收盘差 ≤ 0.05。`model_readiness` 另绑定库 SHA256、
  训练策略、来源、半衰期、先验方法、校准开关与最新两完整季，跨季自动失效。

### 仅说明 / 需要所有者决策

- **P2 可用与评估库 SHA256 强绑定**。`model_readiness` 要求线上模型的 `database_sha256` 等于 tune 时静态库的哈希。
  这意味着任何新增一天数据后重训的模型都会回到「P2 实验」，直到用同一新库重新跑完整 tune（15 联赛数小时）。
  这是保守且可审计的设计，但与 T15 任务单「不做定时自动训练（T16）」衔接时需要决定：T16 是把 tune 也纳入定时任务，
  还是把绑定放宽为「相同来源 + 相同训练策略 + 证据季未过期」。建议写进 T16 任务单。
- **日职赛季边界**。`seasons.CALENDAR_LEAGUES` 把日职按自然年切季。J.League 已宣布自 2026-27 赛季起改为跨年
  （8 月开始），2026 年上半年为过渡赛制。本次评估用到的 2024 / 2025 两完整季不受影响，但 2026「部分季」及之后
  的自然年切分会把过渡联赛和新赛季前半段混在一起。日职当前 `p2_ready=false`，暂无影响；进入 2026-27 前需要给日职
  单独的赛季规则。
- **jc 子集定义**。`jc_linked` 只统计带 `counterpart_id` 的 jc 行或指向 `jc:` 的行，纯 jc 行若无链接不计入。
  与任务单「通过 counterpart_id 链接」的表述一致，但报告读者可能以为是「全部 jc 场次」，建议在报告措辞上明确。
- **`complete` 只看时间窗**。赛季是否「完整」由 `start <= 赛季起点 且 赛季终点 <= as_of` 判断，不检查数据是否真的覆盖整季；
  实际由 n ≥ 500 间接兜底。可接受。
- **验收数值未独立复算**。静态库与全量 JSON 只在实现者工作目录，本审查未重跑真实评估；报告列出的复现命令完整，
  库 SHA256 已登记，可在需要时复现。
