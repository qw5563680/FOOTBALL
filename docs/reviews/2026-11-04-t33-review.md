## 发现

必须修：无。

建议修

1. **数据分支体积**（需所有者决定，不阻塞合并）：`experiments/t33/2026-11-05-round1/` 149 MB 压缩产物使数据分支对象库从 24 MB 增至
   163 MB；`football-feeds.yml` 六个 job 都以 `fetch-depth: 0` 检出该分支（含 Windows 自建 runner），每次定时运行多传约 0.9 GB。
   任务单确实写了「全量结果进数据分支」，所以这是规则问题而非实现偏差。建议：(a) 不重写历史（发布脚本把非快进视为错误，重写风险大于收益）；
   (b) 从 T34 起，实验全量产物改走 Release 资产（如 `experiments-YYYYMM`，与 `stats-raw-YYYYMM` 同机制），数据分支只放 README 与 SHA256SUMS；
   (c) 审查者在下一次定时运行后对比各 job 的 checkout 时长，若明显拖慢再议数据 checkout 改为 `fetch-depth: 1` 或 sparse checkout。

仅说明

2. **选窗口径**：`select()` 用候选原始 LL（含回退行）在选择期比较 N=5/10；N=10 回退行更多，严格说比较的是「候选+回退混合」。
   本轮各联赛 N=10 与 N=5 的 LL 差（0.01–0.03）远大于几行回退能解释的量，选窗结论不受影响；第二轮协议建议改为按共同实验样本选窗。
3. **信息时点不对称**：候选特征按目标开球截点更新（可用到本周早些比赛的统计），基线 DC 参数在周一折点拟合；这对候选略有利，
   候选仍未胜出，因此不影响「无改善」结论。第二轮若要公平比较，可让基线同样按比赛日重拟合，或把特征截点统一到折点。
4. **季界**：`fold_cutoff` 对所有联赛用英超的赛季边界（7 月）。本轮九联赛都是欧洲夏秋赛季，无影响；跨年赛制联赛进入前需改。
5. **荷甲一折的基线差异**：fit_cutoff 2025-11-02 的 9 场，原模型（生产 `DixonColes`）在 scipy 1.17 与 1.18 下收敛到略不同的点
   （最大 1.3 个百分点），其余 300+ 折差异 ≤ 1e-5。这是基线优化器在该折的收敛容差问题，与 T33 代码无关；候选/消融的差异都在 1e-6 量级。
   可作为 T34 前瞻比较时「同一环境固定依赖版本」的理由。
6. **基线 4 场无效矩阵**：生产 `DixonColes` 对 2025/26 法甲 / 法乙 4 场（涉及升班马巴黎 FC、洛里昂、圣埃蒂安）产生含负值的比分矩阵。
   实验按现行实现保留失败、未改旧模型，处理正确；但这暴露的是正式模型的问题，建议另开小任务核查每日预测里这些比赛是否同样无预测
   以及 rho 约束在未知球队先验下的边界处理。
7. **市场列 n=0**：jc 历史报价不足，`attach_market` 在真实数据上未被触发，只有合成测试覆盖；T34 前瞻阶段会首次真实使用，届时再验。
