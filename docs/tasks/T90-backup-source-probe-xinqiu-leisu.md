# T90 备用来源探测：新球体育、雷速体育，以及竞彩的备用渠道

来源：所有者 2026-11-25（同 T89）。这两个网站项目里从来没有探测过，先查清楚能不能用，再决定接不接。

## 要回答的问题

对每一个候选网站，用证据回答：

1. robots.txt 写了什么，足彩 14 场和竞彩赛程的页面路径是否允许抓取，有没有访问时段或频率要求。
2. 这些页面是不是普通网页（不执行 JS 就能读到对阵和开球时间）。需要执行 JS、登录、验证码或专用接口签名的，记为「不可用」。
3. 页面上有哪些字段：期号、场序、赛事、主客队、开球时间、停售时间、比赛编号。
4. 连续几次请求是否稳定（状态码、是否被拦截）。

候选：

| 候选 | 用途 |
| --- | --- |
| 新球体育 | 14 场名单、竞彩赛程 |
| 雷速体育 | 14 场名单、竞彩赛程 |
| 澳客的竞彩页面 | 竞彩赛程（澳客的 14 场页面已在 T89） |

网站的具体网址由实现者从公开首页确认后写进 PR，审查时核对；确认不了的照实写「未确认」。

## 范围

1. 在现有探测框架里增加一个探测种类（参照 `src/zucai/okooo_probe.py` 的 `okooo-sfc`）：
   每个候选只读 robots.txt 和最多 3 个公开页面，间隔不少于 3 秒，保存原始响应的哈希和裁剪后的样本。
2. 探测只在 GitHub Actions 里由 DeepSeek 触发（`operation=probe`），在正式采集机上运行。
3. 探测报告放 `reports/`（只放 `README.md` 和哈希清单，不超过 200 KB），逐条回答上面四个问题，
   每个候选给出结论：可用 / 不可用 / 需所有者决定，并写明依据。
4. 把结论写进 `docs/DATA_SOURCES.md`。

## 不做

- 不接入正式采集，不改日报。接不接、先接哪个，等报告出来由所有者决定，另写任务单。
- 不解析、不保存任何赔率或市场信息。
- 不上浏览器自动化，不绕过反爬、登录或验证码，不调用网站没有公开的接口。
- 开发环境不向这些网站发任何真实请求；离线测试只用仓库里的样本，样本只能来自 Actions 探测的产物。
- robots.txt 禁止的路径不请求。

## 验收标准

1. 离线测试：探测逻辑对「robots 禁止」「返回非 200」「页面需要 JS（正文里没有对阵）」三种情况各有正确分类。
2. 离线测试：单个候选的请求数不超过上限，间隔不少于 3 秒。
3. 工作流只允许通过 `operation=probe` 触发这个探测种类。
4. 合并后由 DeepSeek 触发一次真实探测，报告回填；Claude 核对报告里的结论与原始证据一致后验收。
   这是探测任务，验收的是「问题有没有被证据回答」，不要求候选一定可用。
