## 范围

1. **中国足彩网改为从首页找入口。** 候选配置首页 `https://www.zgzcw.com/`：先读该域的 robots.txt，允许才读首页；
   从首页的静态链接里找 14 场胜负彩和竞彩足球的入口，再去读找到的页面。
   - 入口可能在别的子域（例如 `cp.zgzcw.com`）。跨到另一个域之前，先读那个域自己的 robots.txt，按它的规则判断，不沿用首页域的结论。
   - 只跟随 `zgzcw.com` 及其子域的链接，不跟随站外链接。
   - 首页找不到入口时，照实记录首页上看到了哪些相关链接文字，不再回退到推测的网址。
2. **每个页面留下能说清原因的证据。** 在现有五项之外，样本里再记录（都只是计数和短文字，不保存整页）：
   - 页面标题、正文字节数、静态表格个数、脚本标签个数；
   - 页面静态文字里是否出现「期」「胜负彩」「14 场」「竞彩」「对阵」这类字样，各出现几次；
   - 最多 5 行、每行不超过 200 字的表格文字片段（只取表头和前几行，用来判断结构；不取赔率列，见「不做」）。
   - 据此把「读不到对阵」分成三类写进结论：不是对阵页 / 需要执行脚本 / 是普通网页但结构未识别。
3. **回答稳定性。** 找到并读到对阵的页面，在请求上限之内间隔不少于 3 秒再读一次，比较两次的比赛行数和字段是否一致。
4. **请求上限。** 中国足彩网这一项的页面请求上限由 3 次调到 6 次（首页 1 次、两个入口各 1 次、稳定性复读各 1 次，留 1 次余量）；
   robots.txt 每个域 1 次，不计入页面上限。其他候选的上限不变。间隔仍然不少于 3 秒，并遵守各域 robots 公布的间隔和时段。
5. **回填。** 探测报告与 `docs/DATA_SOURCES.md` 回填两轮真实探测的结果（运行 45826832242 与本任务合并后的新一轮），
   各附运行链接、附件名与哈希。结论只写证据支持的内容；仍然说不清的照实写「未确认」。
6. 澳客竞彩页保留为对照，同样使用第 2 点的新证据项。

## 不做

- 不接入中国足彩网，不把它用于任何正式采集。是否接入由所有者看了结果再定，另开任务单。
- 不读取、不保存、不解析赔率和奖金。表格片段里出现数字列时，只保留赛事、主客队、时间、期号、场序这几类文字。
- 不执行页面脚本，不引入浏览器自动化（任务规则第 7 条）。页面必须执行脚本才显示对阵时，结论写「需要执行脚本」，到此为止。
- 不在开发环境发任何真实请求。真实探测由 DeepSeek 在 Actions 触发（`operation=probe`，`probe_kind=backup-sources`），在所有者的采集机上运行。
- 不请求 robots 禁止的路径（已知 `cp.zgzcw.com` 禁止 `/homePage/`）。

## 验收标准

1. 离线测试：首页样本里有入口链接时，探测去读找到的页面；入口在另一个子域时先读该域的 robots；robots 禁止时不请求。
2. 离线测试：首页没有入口链接时不回退到推测网址，报告写明首页上看到的相关链接文字。
3. 离线测试：三类「读不到对阵」各有一个样本，结论分别正确；能读到对阵的样本给出字段覆盖和复读比较。
4. 离线测试：样本文件里没有赔率和奖金数字；页面请求数不超过上限，间隔不少于 3 秒。
5. `tests/test_windows_collection_machine.py` 通过。
6. 合并后由 DeepSeek 触发一次真实探测。Claude 核对附件：四个问题（访问规则、是不是普通网页、有哪些字段、是否稳定）
   每个都有证据支持的答案，或者明确写出卡在三类原因里的哪一类。答案齐了，T92 与本任务一并验收；不要求候选一定可用。
