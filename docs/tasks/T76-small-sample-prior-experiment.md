# T76 小样本先验：并行实验线（正式模型不动）

来源：`docs/proposals/2026-11-19-rating-carry-over-and-priors.md`；所有者 2026-11-18T22:18:54Z 决定：
**小样本先验选乙——先作为并行实验线，保留正式模型和已积累的成绩。** 并要求：

1. 回放脚本和参数提交入库；
2. 先修正身份，再让新旧模型用相同比赛、相同截止时间对照；
3. 0 场、1–5 场、6–12 场、13 场以上分别记分；
4. 上下级联赛打通另做一组对照，看它在加先验之后还能额外改善多少；
5. 达到项目原有转正标准后，再决定是否替换正式模型。

实现与审查分工按所有者当前安排（Claude 实现并开 PR，DeepSeek 审查与合并）。PR 标题以 `T76:` 开头。

## 现状

- 正式球队模型按联赛各自拟合 Dixon-Coles。一支球队在本联赛只要有 1 场已知比赛，就按这几场直接估计，没有任何收敛；
  0 场时才用通用弱队先验（`weakest_quartile_half_shrinkage`）并标「默认实力」。
- 探索性回放（临时脚本，未入库，8 个联赛、三个完整赛季、8,616 场）：一方近一年在本联赛只有 1–5 场的比赛，
  现行模型 Log Loss 1.171，差于三选一各 1/3 的 1.099；加先验后 1.053。双方都在 13 场以上的比赛（87.5%）基本不变。
  这些数字只说明值得做，不作为采用依据；本任务单要求用入库的脚本重做。
- 身份问题会污染这类统计（例：法乙南锡被拆成两个身份时只读到 1 场）。法乙 7 支已在 PR #206 修正，
  其余联赛的缺口见本单「前置条件」。

## 定义（写死，回放与每日实验线共用）

- **已知场数 n**：截点前 365 天内，该队在本联赛、赛果可知时间不晚于截点的比赛场数。
  训练行一律经 `select_training_history(history, cutoff)` 选取，可知时间口径不改。
- **分段**：按一场比赛双方 n 的较小值分为 `0`、`1–5`、`6–12`、`13+` 四段。整体数字不得代替分段数字。
- **先验（dc-prior）**：在现行拟合结果上做后处理，不改拟合本身。某队的进攻、防守参数改为
  `(n·实际估计 + k·先验目标) / (n + k)`。先验目标：该队上一赛季不在本联赛 → 弱队先验（与现行「默认实力」同一算法）；
  否则 → 联赛平均。主场优势与低比分修正不变。
- **上下级打通（dc-tier）**：同一国家上下两级联赛的已知比赛放在一起拟合（复用欧战已在用的多联赛拟合），其余不变。
- **四个版本**：`dc`（现行）、`dc-prior`、`dc-tier`、`dc-prior-tier`。
- **k 的取值**：候选 `3、6、10`。只在选参季上选（取选参季全部回放场次 Log Loss 最小的，并列取小），验证季上不再调整。
- **基线就是正式模型**：每个联赛、每个赛季用参数文件里该赛季自己的选参结果（`evaluation_windows` 的半衰期与平局校准），
  经项目的 `DixonColes` 类拟合与预测。先验与打通版本只替换球队强度（打通版本另带联合拟合的主场优势与低比分修正），
  其余走同一条预测路径（低比分修正的合法区间保护、比分矩阵、平局校准都相同）。

## 范围

### A. 回放工具入库

1. 模块 `src/zucai/predict/experiments/prior_replay.py`（`python -m zucai.predict.experiments.prior_replay replay|score`）：
   把四个版本对同一批比赛、同一截点逐周回放，逐场输出各版本的主平客概率、双方 n、上一赛季是否在本联赛、实际赛果。
2. 参数文件 `data/experiments/dc-prior/replay.json`：联赛与上下级配对、赛季、k 候选、365 天窗口、分段边界、
   自助法种子 `3301` 与次数。这些值只从参数文件读，不设命令行覆盖。
3. 记分：按分段输出场数、Log Loss、Brier、最高项 ≥80% 的场数与实际命中率；
   配对差用仓库已有的按周整块自助法（`zucai.predict.experiments.metrics.paired`）给 95% 区间。
4. 选参与验证分开：选参季 2024–25，验证季 2025–26，k 在选参季上定、验证季上固定。
   参数文件里各联赛逐季的选参记录从 2024–25 起才有，所以 2023–24 不回放（没有当季的正式参数可对照）。
   2026–27 赛季因项目 11 月才开始采集、此前竞彩赛果可知时间偏晚，单列、不并入结论。
5. 报告 `reports/t76-prior-replay/README.md` 加 SHA256 清单（逐场 CSV 不入库，写明重现命令、数据分支提交与库哈希）。
6. `README.md` 快速开始补一行用法。

### B. 每日并行实验线 `dc-prior-v1`

1. 接入现有实验线通道（`zucai.predict.experiments.parallel` / `experimental_archive.freeze_parallel`）：
   与正式预测同一截点、同一批比赛、同批冻结；正式预测先冻结，实验线失败不影响正式预测。
2. 覆盖全部已开放的联赛型赛事（不含欧战合并模型与国家队赛事）。k 用 A 段验证通过的值，写入模型定义并随预测披露。
3. 冻结行披露：`prior_method`、`prior_strength_k`、双方 n、双方先验目标（弱队 / 联赛平均）。
4. 日报「实验模型」表与记分板增加这一栏，并按 `0 / 1–5 / 6–12 / 13+` 四段分别计分；与正式模型同场配对。
5. 不进入虚拟账户、纸面串关、任九候选与主候选；标签固定为「实验」。

### C. 上下级打通的对照（只回放，不上每日线）

1. 用 A 的工具输出 `dc-prior-tier` 相对 `dc-prior` 的配对差（同样分段、同样区间算法），回答
   「加了先验以后，打通还能额外改善多少」。
2. 结论写进同一份报告；是否把打通也接入每日实验线，由所有者看过结果后另行决定。

允许改动：`src/zucai/predict/experiments/`、`src/zucai/experimental_archive.py`、记分板与日报里实验模型一栏的代码，
`data/experiments/`、`tests/`、`data/fixtures/`、`reports/t76-prior-replay/`、`README.md`、`docs/ARCHITECTURE.md`。

## 验收

1. 四个版本在同一批比赛上逐场配对：每个版本的场次集合、截点完全一致，报告里给出场数核对。
2. `dc` 的回放概率与现行正式模型类 `DixonColes` 在同一截点的输出逐场一致（差不超过 1e-9），证明对照的基线就是正式模型。
3. 离线测试只用 `data/fixtures/` 的样本：先验公式（n=0、n 很大、上一季在/不在本联赛）、分段边界（0、5、6、12、13）、
   自助法在固定种子下逐字重现、k 只在选参季上选。
4. 前视检查：任一截点的训练行里没有可知时间晚于截点的比赛；先验目标只由截点前的比赛算出；测试覆盖。
5. 红线检查：不读取赔率、收盘价或任何市场信息（测试断言回放与实验线的输入里没有市场字段）。
6. B 段：正式预测、既有实验线、账本、任九、纸面串关的冻结文件逐字节不变；新增的只有 `dc-prior-v1` 的冻结行与展示。
7. 全量 `pytest -q`、`ruff check src tests`、`ruff format --check src tests` 通过；测试不联网。`reports/` 新增不超过 200 KB。

## 失败标准（沿用提案）

1. 验证季「13+」一段，`dc-prior` 相对 `dc` 的 Log Loss 差 95% 区间上界超过 +0.002：不上每日线。
2. 验证季「0、1–5、6–12」三段合并，差的 95% 区间上界不小于 0：不上每日线。
3. 每日线攒满 100 场「一方 ≤12 场」的前瞻配对样本时，差的 95% 区间下界大于 0：停掉这条实验线。
4. 任何时候发现先验用到截点之后的数据或任何市场信息：立即停用并复盘。

## 不做

- 不改正式模型的拟合、参数、冻结、成绩与转正计数；是否替换正式模型按 `docs/PROMOTION-PROTOCOL.md` 另行评审。
- 不使用赔率、收盘价、球员身价或任何市场信息。
- 不新增数据来源与请求。
- 不改身份合并规则；不在本任务里批准任何队名对照。
- 实验线名额：现有射正、预期进球、球队＋市场融合三条，加上本条共四条，已到上限；本任务不再新开别的线。
