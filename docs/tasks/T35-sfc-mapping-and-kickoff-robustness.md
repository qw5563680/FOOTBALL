# T35 · 14 场胜负彩：开球时间占位值、身份映射缺口与报告冻结条件（T26 后续，小修）

## 背景
第 26158 期（截止北京 2026-11-04 17:30）真实运行暴露三处 T26 缺口（数据分支 `state/sfc/26158.json`）：
1. 500.com 胜负彩页对第 2 场「布里兰 VS 鹿岛」给出 `kickoff_utc=2026-11-03T16:00:00Z`（北京 11-04 00:00），实际开球 20:15。
   T26 的「任一场已开球则不发布报告」把这个占位时间当成已开球，整期报告在截止前**一次都没有冻结**，摘要 14 行全显示「尚无冻结概率」。
2. 两场亚冠（浦项–大阪钢巴、布里兰–鹿岛）映射 `ambiguous / conflicting_identity`：库内同窗有 jc 亚冠精英比赛，但 500 的球队 ID 与库内 jc 身份对不上。
3. 三场英冠、一场巴甲 `unmatched / exact_team_names`：500 短名（加的夫、雷克斯、米德尔、布里斯、伍尔弗、弗拉门、格雷米）与库内 jc 名不同，且这些场次当时 jc 尚未开售，没有 jc 桥接。

## 范围
1. **开球时间**：映射成功（`matched`）的行一律以库内比赛的 `kickoff_utc` 为准；未映射行若 500 时间为整点 00:00（北京）且与同期其他比赛日期不一致，标 `kickoff_basis=placeholder`，**不**参与「已开球」判定，仍在报告中保留并标注。
2. **报告冻结条件**：改为「截止前且所有**已映射**比赛未开球」；未映射行不阻断发布，在报告里显示「未映射：原因」。
3. **亚冠映射**：对 `conflicting_identity` 行把 500 球队 ID、jc 候选和冲突双方写进 `state/audit/sfc_unmatched.csv`（已有表补列），并在下一次 jc 同步后重试映射；不按名字猜。
4. **英冠 / 巴甲 短名**：500 的 `provider_home_id / provider_away_id` 与 jc 页的同一 ID 体系一致（T26 已用于欧冠），对未开售场次在 jc 开售后的下一次 sync 自动补映射；报告每次重算映射，不冻结失败状态。
5. 摘要：14 场表区分「未映射」「占位开球时间」「无模型」三种原因；复式项对无模型行继续 `3+1+0` 全包并写明「全包＝无预测」。
6. 测试（`data/fixtures/t26` 扩展）：占位 00:00 不阻断发布；已映射行用库内开球；未映射不阻断；重试映射幂等。

## 不做
- 不改赛果结算规则、不建账户、不估奖金；不按名字相似度绑定；不改 jc / fd / fdorg 身份规则。

## 验收标准
- 离线测试全绿、ruff 通过。
- 真实验收（审查者）：下一期胜负彩在截止前至少一次成功冻结 `sfc/<issue>/report.*`；摘要 14 行显示概率或明确原因；占位开球时间行不再触发「已开球」。
