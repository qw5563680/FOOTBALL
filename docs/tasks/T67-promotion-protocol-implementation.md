# T67 落地赛事转正评审规程：版本绑定的批准、场次记账、评审报告

来源：所有者 2026-11-14 确认的 `docs/PROMOTION-PROTOCOL.md`（v1，定稿未生效）。
分支 `codex/T67-promotion-protocol-implementation`，PR 标题以 `T67:` 开头。
**合并顺序：T66 上线，T63 上线，然后才合并本单。本单合并入 main 的时间即规程生效时间。**

## 范围

规程原文是唯一依据，本单只列实现要点；实现与规程不一致时以规程为准并在 PR 写明。

1. **版本标识**：按规程第 7 节给每个赛事的模型算出稳定的版本标识
   （赛事、模型族、训练来源集合、拟合方法、先验方法、校准方法、选参协议），
   与每天变化的模型文件哈希分开。每条冻结预测都带版本标识。
2. **批准记录**：新增入库的批准登记（建议 `data/model/approvals.json`），逐条为
   赛事、适用范围、被批准的版本、依据、所有者批准日期。初始内容为七个旧规联赛的旧版本，
   依据写「旧规则」。批准登记只能通过 PR 修改，PR 须引用所有者的批准。
3. **纸面账户与版本对齐**：虚拟单场与纸面串关只使用「作答版本等于被批准版本」且标签允许的预测。
   每笔纸面记录保存作答版本、批准版本与批准依据。对不上的不得入账，并在排除原因里写明。
   已冻结的旧账本不回写。
4. **标签四态**：可用、可用（旧规，考核中）、实验、暂停，含义见规程第 10 节；
   日报、报告、记分板、14 场报告统一使用。足彩独有场次的标签不随竞彩场次的批准改变。
5. **历史比例基线**：每个批次在冻结模型预测的同时，冻结该赛事的历史比例预测（规程第 2 节），
   事后不得重算。
6. **场次记账与进度**：按规程第 3 节为每个赛事的每个版本维护记账表（开售、作废、作答、
   漏答原因、有无同期报价及原因），记分板在两次评审之间只显示进度与记账表。
7. **评审报告**：到体检点、首次评审点与复核日，生成评审报告（规程第 5、6 节的全部指标、
   两种口径、平局三项呈报），结论只有达标、明确不达标、分不清。报告只生成、不自动改标签。
8. **杯赛分组**：从配置读取 T62 的分组成员名单；开考后名单变化视为配置错误并拒绝。
   T62 未上线前，分组配置可以为空，本单的机制须能在之后只加配置就启用。
9. **历史门槛修订**：`min_evaluated` 由 500 改为「最近两个完整赛季的全部已赛场次且不少于 300 场」，
   仅作参考展示；不因此改变任何赛事的标签。
10. **生效时间**：写入配置并在记分板显示；计数只统计生效之后各版本自己的赛前预测。
11. **训练历史换代登记**（2026-11-14 增补）：批量回填使某个赛事可用于训练的历史范围变化时，
    版本标识不变，但预测已经不同。例：2026-11-14 第二批目录回填后，欧战训练行数由 20,608 变为 27,999，
    美职、韩职、澳超、日职、瑞超、挪超、芬超也有增加。记账表须登记换代日期与前后训练行数；
    评审报告把换代前后的预测分段列示。分段之后是否合并计数，由所有者在评审时决定，本单不预设。

## 验收

1. 离线：用固定归档副本回放，验证生效前的预测不计数；作答定义、漏答原因、同期报价配对与规程一致；
   非评审时点不出结论；两种口径相反时结论为分不清。
2. 版本对齐：作答版本与批准版本不一致的预测不进入纸面账户；每笔新纸面记录都能读出两个版本与依据；
   七个旧规联赛在规程生效当天的纸面账户行为与生效前一致（列对比）。
3. 标签：四态在日报、报告、记分板、14 场报告中一致；足彩独有场次不因联赛被批准而变为可用。
4. 泄漏与红线：历史比例只用截点前可知的赛果；竞彩赔率只进入评分对照，不进入训练、先验、校准、选参；
   BET 禁用。
5. 既有模型的训练输入与概率不因本单改变（同一归档副本前后对比）。
6. 全量 pytest、ruff 通过；测试只用 `data/fixtures/`；`reports/` ≤ 200 KB；
   README、ARCHITECTURE 同步（含新增的表或文件）。
7. 线上（审查者执行）：合并后连续三次每日链路成功；记分板显示生效时间与各赛事进度；
   七个旧规联赛的纸面账户记录带有版本与批准信息。

## 不做

- 不改任何模型的训练方法、参数与来源；不替所有者批准或降级任何赛事。
- 不回写冻结预测、旧报告、旧评分、旧账本。
- 不把历史回测结果用于转正；不追认挪超、瑞超、芬超。
