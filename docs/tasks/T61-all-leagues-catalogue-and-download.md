# T61 所有接口、所有相关联赛：总目录、对照表、历史下载、每日采集

来源：所有者 2026-11-14 指示「要把所有接口的联赛数据都给模型训练，这才是开付费的目的」。
分支 `codex/T61-all-leagues-catalogue-and-download`，PR 标题以 `T61:` 开头。
本单只管数据进库，不改任何模型与预测；建模在 T60（四联赛）与 T62（其余全部）。

## 现状（审查者实测，数据分支 `040bc62`）

- 归档里竞彩 2026-09 以来卖过 38 个赛事，只有 19 个有模型。没有模型的 19 个：
  韩职、澳超、日乙、荷乙、德乙、沙职、亚冠精英、亚冠乙、解放者杯、日联赛杯、英联赛杯、英锦标赛、
  德国杯、意大利杯、荷兰杯、巴西杯、国际赛、亚运男足、亚运女足。
- API-Football 的联赛集合写死在 `src/zucai/sources/api_football.py:24-26`（11 个可导入、7 个仅身份、
  欧冠仅索引）；probe、回填、每日采集都只认已配置的这些联赛，接口里其余联赛从未列过目录。
- football-data.org 只用了欧冠；football-data.co.uk 的 `D2` 因身份歧义禁止导入。
- Sportmonks 未接入：仓库没有它的代码与密钥，本单不涉及。

## 范围

### 一、联赛总目录（先拿到「接口到底有什么」的实证）

1. 新增只读探测 `probe_kind=catalogue`（仅 Actions `workflow_dispatch`，审查者触发）：
   API-Football `/leagues` 全量一次、football-data.org `/competitions` 一次；原件与解析结果
   （联赛 ID、名称、国家、类型、各赛季是否有赛程与赛果覆盖）落到数据分支 `state/catalogue/`，
   不导入任何比赛。football-data.co.uk 的目录用已核实的 `DIV` 清单。
2. 先读两站 robots.txt 与条款，结论写进 `docs/DATA_SOURCES.md`。

### 二、赛事对照表

1. 入库一份 `竞彩/足彩赛事名 → 各接口联赛` 对照表（建议 `data/league_map.json`），每行带
   `status`（`verified` / `candidate`）与证据（目录里的名称、国家、赛季）。
2. 只有 `verified` 的行才允许回填与采集。核准走 PR，由审查者对照目录原件确认；
   不做名称模糊匹配后的自动核准。
3. `APIF_LEAGUE_IDS` 等写死集合改为读对照表；既有 11+7+1 个联赛的行为逐字节不变
   （`identity_only`、`index_only` 语义保留）。

### 三、下载范围：全部相关联赛、全部可读赛季

「相关」的定义（三类，全部要下）：
- A. 竞彩或足彩出现过的每一个赛事；
- B. A 类杯赛与洲际赛参赛球队所在国家的各级联赛与国内杯赛（否则杯赛没法建模）；
- C. 国家队比赛：世预赛、洲际杯及其预选赛、欧国联、友谊赛。

与任何在售比赛都没有交集的联赛只在目录里登记、不下载（它们进不了任何一场预测）；
所有者要求全下时改一个配置即可，不得写死排除。

1. 回填操作改为按对照表取联赛，按目录取可读赛季；支持断点续跑与每次运行的请求上限，
   给每日采集留足配额（Pro 每日 7,500 次；回填只取赛程赛果，每联赛赛季一次请求）。
2. 每日采集同步覆盖 A、B、C 全部联赛，赛果持续入库。
3. 球队身份沿用既有流程（identity、reconcile、relink-jc、候选队列）；未核实的球队保持待核，
   不合并、不模糊匹配。新增联赛的竞彩队名对不上时进候选队列，不阻断下载。
4. 报告体积与耗时：PR 写明新增比赛数、数据库大小、`restore_feeds` 与每日链路耗时的前后对比；
   原始响应按既有规则放数据分支或 Release 附件，不进 `reports/`。

## 验收

1. 离线：目录与对照表解析只用 `data/fixtures/` 样本；对照表为 `candidate` 的联赛回填被拒。
2. 既有联赛不回归：同一归档副本改动前后，既有来源的比赛、赛果、身份、链接表逐字节一致；
   既有模型训练输入不变（T60 之外的 `params.json` 条目不动）。
3. 线上（审查者执行）：目录探测一次成功且原件入库；按对照表分批回填，直到 A、B、C 全部
   `verified` 联赛的可读赛季入库；之后连续三次每日链路成功，且新联赛当日赛果出现在库里。
4. 交付一张覆盖表：38 个竞彩赛事逐个列出对应接口联赛、已入库赛季与场数、仍缺什么及原因。
   接口确实没有的赛事（例如亚运男足、女足若无数据）如实标「接口无」，不得用合成数据填。
5. 全量 pytest、ruff 通过；`reports/` ≤ 200 KB；README、ARCHITECTURE、DATA_SOURCES 同步。

## 不做

- 不改模型、参数、预测、记分板、报告；不让赔率或市场信息进入任何模型输入。
- 不采逐场技术统计（射门、xG、阵容、伤停）：那是另一条实验线，按提案模板另议。
- 不在开发环境用正式 key 联网；不新购服务；不引入浏览器自动化。
- 不回写冻结预测、旧报告、旧评分、旧账本。
