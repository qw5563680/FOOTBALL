# T62 给全部新入库赛事建模：国内联赛逐个配置，杯赛、洲际赛、国家队用「池」

来源：所有者 2026-11-14 指示（所有接口的联赛数据都进训练）。依赖 T60（来源配置机制）与
T61（数据入库）；两者合并且回填完成后开工。
另依赖 T68（球队身份绑定）：某赛事的球队绑定完成后才能为它建模。（2026-11-14 补充）
分支 `codex/T62-models-for-all-leagues-cups-nations`，PR 标题以 `T62:` 开头。

## 范围

范围依据：`docs/research/2026-11-14-jc-sfc-competition-master-table.md` 的第 3 至 8 组，共 69 个赛事。
下文列举的赛事只是举例，以总表为准；总表里每个赛事在交付时都要有结论：
能预测，或写明不能预测的具体原因。

### 一、国内联赛：有历史就有模型

1. T61 入库的每个国内联赛（总表第 3 组：德乙、荷乙、日乙、沙职、英甲、俄超）
   按 T60 的机制加入来源清单与 `params.json`，`p2_ready=false`，报告标「P2 实验」。
2. 参数：完整赛季够跑既有协议的按协议选半衰期；不够的用固定 365 天并写明「未调参」。
3. 既有 15 联赛不改来源：付费接口对它们提供的是同一批比赛的同一份赛果，模型已有，
   加入不增加任何一场训练样本，却会让已通过的 P2 证据作废。若实测发现接口有、现有来源缺的
   场次，列出场次数再议，不在本单擅自改。

### 二、杯赛、洲际赛、国家队：把欧战池的做法做成可配置的「池」

1. `predict/pooled.py` 的单一 `POOL="欧战"` 改为配置驱动的多个池；欧战池的定义、参数、
   模型文件哈希与预测逐字节不变。
2. 新增的池由配置给出「目标赛事」与「训练范围」，覆盖总表第 4 至 8 组，例如：
   - 日本：日联赛杯（训练含日职、日乙及其以下已入库联赛）；
   - 英格兰：英联赛杯、英锦标赛（英超至英乙）；
   - 德国杯、意大利杯、荷兰杯、巴西杯（各自国家已入库的各级联赛）；
   - 亚洲：亚冠精英、亚冠乙（参赛球队所在国家的顶级联赛）；
   - 南美：解放者杯；
   - 国家队：国际赛（与欧国联、世预赛、洲际杯同池；是否并入现有欧国联模型由实现者给出
     方案与理由，现有欧国联预测在并入前后须可比）。
3. 池内跨联赛强度只来自真实交手（杯赛、洲际赛、升降级带来的共同对手）；
   两个联赛之间没有任何连接时，该池不得给出预测，原因写进排除理由。
4. 升降级附加赛（总表第 4 组）按上下两级联赛同池处理；各国超级杯、欧洲超级杯这类
   对阵双方已在某个现有模型内的赛事，直接路由到该模型，不另建池。
5. 青年、女足、综合运动会（总表第 8 组）：这些队伍与成年男足不是同一支队，不得借用成年队强度。
   接口有历史的单独成池；接口无数据的保持不预测，排除理由写成说人话的一句
   （例如「接口没有该赛事的历史数据」）。

## 验收

1. 逐字节不变：既有 15 联赛、欧战池、欧国联的模型哈希与预测在同一归档副本上前后一致
   （欧国联若按方案并池，单独给出并池前后同一批场次的对比，不替它们平均）。
2. 覆盖表：对数据分支当时全部竞彩场次重放，逐赛事列出「可预测场数 / 总场数」与每类排除理由；
   目标是 T61 覆盖表里有数据的赛事全部进入可预测。
3. 泄漏与红线：训练只用截点前可知的赛果；赔率不进训练、先验、校准、选参；BET 禁用。
   新增测试覆盖「池不连通拒绝预测」「目标赛事不在训练范围被拒」「多池注册不互相覆盖」。
4. 评估口径：新模型一律前瞻评估，沿用现有 gate；历史回测数字只作说明。
   与任何旧模型比较只认同一批比赛按 ID 配对、事前冻结协议、Log Loss 主指标、分母相同。
5. 线上（审查者执行）：合并后连续三次每日链路成功，新赛事出现冻结预测并进入记分板。
6. 全量 pytest、ruff 通过；`reports/` ≤ 200 KB；README、ARCHITECTURE、DATA_SOURCES 同步。

## 不做

- 不改既有模型的参数与来源；不回写冻结预测、旧报告、旧评分、旧账本。
- 不用逐场技术统计；不引入深度学习或其他重型依赖。
- 不为没有历史数据的赛事编造先验或用赔率倒推强度。
