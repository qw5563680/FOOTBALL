## 现状（main `1fc08b5`，数据分支 `a87f2757`）

- 接口（API-Football）里有后续赛程、但库里只有临时身份 `apif:team:<编号>` 的欧战球队共 27 支。
  其中 2 支（比尔森、比亚韦）库里已有竞彩建立的同名身份，已在 #251 按旧做法补上并合并。
- 剩下 25 支里，11 支在已归档的竞彩官方赛果里能找到名字和官方球队编号，但库里还没有这支球队的规范身份。
  旧的合并流程遇到这种情况会跳过（`apif_reconcile.py`：「规范球队在库中缺失」），所以必须先建档。
- 建档走 T68 的工具。在数据分支副本上离线运行的结果：
  - `python -m zucai.identity_canonical plan --archive <归档> --codes 3,848`：给出 40 条建档提案，
    但 40 条的既有球队结论全部是 `pending_review`，原因都是
    「绑定提案未给出唯一且见证齐全的接口球队编号 X」。`apply` 只接受结论为「新建」的提案，所以一条都建不了。
  - `python -m zucai.identity_binding --archive <归档> --out <目录> --leagues 3 848`：
    官方赛果 227 场里，191 场是「缺少准确开球时刻，日期或占位时间不能作证」（`missing_kickoff_evidence` 191，
    `jc_verified_clocks` 只有 36）。
- 根本原因：官方赛果目录只有比赛日期，没有开球时刻。补开球时刻的探测（`probe_kind=jc-kickoffs`，
  `src/zucai/jc_catalogue_kickoffs.py`）只覆盖 T65 核准的 62 个新赛事（`APPROVED_ROUTE_IDS`，并要求每个赛事带 #135 的核准证据），
  欧罗巴（接口赛事编号 3）和欧协联（848）是更早接入的赛事，不在名单里。

## 范围

1. **官方开球时刻的探测覆盖欧罗巴（3）和欧协联（848）。**
   - `jc_catalogue_kickoffs` 的清单生成与探测把这两个赛事在十二个月官方目录里的场次纳入（目前缺时刻的是 191 场）。
   - 这两个赛事是旧赛事，没有 #135 的核准证据。实现时给它们单独的准入依据并写明出处，
     不放宽 62 个新赛事现有的检查，也不借此把别的赛事带进来。
   - 请求规则不变：竞彩官方逐场接口，限速 1 秒，原件与 sidecar 照现有格式归档，按请求上限分批、可重复执行自动补齐。
2. **时刻补齐之后，现有工具对这两个赛事能给出结论。**
   - `identity_binding --leagues 3 848` 对证据齐全的球队给出 `strict_verified` 或 `conditional_verified` 的绑定提案。
   - `identity_canonical plan --codes 3,848` 的既有球队结论不再因为缺时刻而停在 `pending_review`：
     该「新建」的给「新建」，库里已有的给「关联既有球队」。
   - 如果补齐时刻之后还有别的环节挡住（例如类别登记、旧条目与带范围条目并存的处理），一并修到能用，
     并在 PR 里逐条写明挡在哪里、怎么改的。**证据规则不放宽**：不用名称相似度，不靠比分挑候选，不凭译名。
3. **从批准到合并的整条路在副本上走通。** 用归档副本离线演示一遍，并写成测试：
   批准清单（`data/identity_reviews/t68-canonical-approvals.json` 的格式）→ `canonical-apply` 建档 →
   别名表条目 → 合并存量比赛（`reconcile` 或范围合并，选哪条路由实现者定并说明理由）。
   结果必须满足：临时身份的存量比赛并到规范身份，比赛总数和赛果总数不变，再跑一次合并 0。
   欧罗巴、欧协联现有的不带范围的旧条目（#34、#82、#251）行为不变。
4. `README.md` 与 `docs/ARCHITECTURE.md` 同步：这两个赛事现在怎样补时刻、怎样出提案。
