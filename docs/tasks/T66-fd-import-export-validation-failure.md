## 范围

1. 修复校验与导入的不一致：fd 导入把竞彩比赛的 counterpart 设为「与该条关联相同的 fd 场次键」时是一致状态，
   不应被拒；实现方式由实现者选择并说明（校验接受该一致状态，或导入时在同一事务内同步关联证据）。
   其他来源的 counterpart、不同的 fd 键、主客反向、共享球队、候选不唯一等情形必须继续拒绝。
2. 排查同类：另外 51 条目标 counterpart 为 `fdorg:` 的关联，在 fd 导入走 `fd_ingest.py:293`
   （把 fdorg 行的 counterpart 设为 fd 键）之后是否触发其他校验，逐类写明结论。
3. 采集时机：`fd_due` 依赖周一早班，早班缺跑就整周不采。至少做到「周一早班未成功采集时，
   当天后续班次补采」；更稳妥的做法是按距上次成功采集的天数判断。选定做法并写明。
4. 回归测试覆盖「关联已存在，之后 fd 导入」的先后顺序；T48 既有拒绝场景的测试不得删除或放宽。
