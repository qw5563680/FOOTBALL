## 范围

1. **复盘回读冻结批次里的未预测原因。** 对清单里没有赛前预测的每一场，查找截点不晚于该场开球的冻结批次中
   该 `match_id` 的未预测记录；有多条时取截点最晚的一条。只用冻结批次原文，不用开球后才生成的批次补原因，
   不从编号、联赛名或别的场次推断。
2. **分类改为四类逐场归类**（原「尚未进入预测窗口」「开球时间缺失」两类不变）：

   | 类别 | 条件 | 是否计入漏预测 |
   | --- | --- | --- |
   | 模型范围外未预测 | 冻结批次写明原因为「缺少同来源同联赛的模型」 | 否，单列 |
   | 确定漏了（原因已知） | 有同步跳过记录，或冻结批次写明了其他原因（如「预测截点时已开赛」） | 是 |
   | 原因未查明 | 以上记录都没有 | 是 |

   同一场既有同步跳过记录又有冻结批次原因时，两条都列出，按同步跳过记录归类。
3. **汇总句与逐场行。** 汇总句增加「模型范围外未预测 N 场（不计入漏预测）」；逐场行写出原因原文、
   来源批次的 run 标识与截点时间（北京时间）。「原因未查明」的行写明查过哪几类记录而没有找到。
4. **机器可读输出同步。** 日报 JSON 与通知摘要里的漏预测计数按新分类输出，「漏预测合计」不含模型范围外。
5. **第一屏兜底句。** 删除「该批次无未开球比赛；已开球场次见复盘。」这句兜底。拿不到可靠事实时改写中性句
   「本批次未列出未开球比赛；今日预测与复盘见下方各表。」，不对「有没有未开球比赛」下断言。

允许改动：`src/zucai/digest_context.py`、`src/zucai/digest_views.py`、`src/zucai/daily_digest.py`，
