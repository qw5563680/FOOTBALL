# T86 每场比赛的爆冷预测（竞彩与 14 场）

来源：所有者 2026-11-25「还要再新增一个功能，就是每一场比赛的爆冷预测，包括竞彩跟14场足彩比赛场次」。
口径由所有者当天选定为 A：只按球队模型算，不用赔率。

## 口径（所有者定）

- 热门方：球队模型胜、平、负三个概率里最高的那个结果。并列时按主胜、平、客胜的固定顺序取第一个。
- 爆冷：热门方没有打出。爆冷概率 = 1 − 热门方概率。
- 最可能冷在哪：概率第二高的结果。
- 不使用赔率、收盘价或任何市场信息。

## 范围

1. 日报里每一张出胜平负概率的表都加「爆冷」一栏：竞彩的今日、明日、销售日跨午夜三张表，以及 14 场的表。
   这一栏写三样：爆冷概率、最可能冷在哪个结果、档位。
2. 档位事先固定，写成代码常量并记入 `docs/ARCHITECTURE.md`，上线后不随成绩调整；要改须所有者决定并记下日期：
   - 高：热门方概率低于 45%；
   - 中：热门方概率在 45%（含）到 60%（不含）之间；
   - 低：热门方概率不低于 60%。
3. 下面四种场次不给档位，写「不评」并写明原因：用默认实力的球队、身份待核、占位开球时间、没有模型概率。
4. 只从已经冻结的预测概率算出来：不新增模型、不重新训练、不改已冻结的预测。
   同一场比赛的爆冷栏跟着它所属的那一版冻结预测走。
5. 赛后复盘新增「爆冷预测成绩」小表，按档位统计：场次数、实际爆冷的场次数、实际爆冷率、赛前平均爆冷概率。
   这张表单独统计，不进入正式模型成绩、虚拟账户和纸面串关；只统计发报时还没开球的冻结预测，同一场比赛只计一次。
6. 文字只作诊断。日报不得出现「推荐」「建议购买」（`digest_notify` 会拒发含这些词的日报），BET 照旧禁用。
7. 同步 `docs/ARCHITECTURE.md`。

## 不做

- 不用赔率或任何市场信息，不标「模型与市场相反」。
- 不改模型、训练、校准和选参。
- 不改任九和复式的选法（任九复式是 T87）。
- 不改历史归档。只加一栏，不新增章节，避免日报再变长（参见 T80）。

## 验收标准

1. 离线测试：概率 50/30/20 → 爆冷 50%、冷在平、档位中；44/30/26 → 爆冷 56%、档位高；60/25/15 → 爆冷 40%、档位低。
   正好 45% 和正好 60% 两个边界各有一例。
2. 离线测试：并列最高（如 40/40/20）按固定顺序取热门方。
3. 离线测试：四种「不评」各一例，原因文字正确。
4. 离线测试：用固定样本核对复盘小表每一档的场次数和实际爆冷率；跨午夜批次里的同一场比赛不重复计数。
5. 同一份冻结预测重放两次，爆冷栏逐字相同。
6. 日报里没有被禁的词；现有测试全绿。
7. 合并后验收（Claude）：正式日报的竞彩表和 14 场表都有爆冷栏，数字与同一行的概率对得上；
   第一批带爆冷栏的比赛结束后，复盘里出现「爆冷预测成绩」小表。
