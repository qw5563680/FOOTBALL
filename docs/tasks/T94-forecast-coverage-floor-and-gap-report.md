# T94 每一场都要有预测：兜底预测与缺口清单

来源：所有者 2026-11-26：「竞彩比赛和 14 场比赛的场次都要给得到预测，要直接把这个问题从后面出现的比赛都避开，
再也不准出现这样的问题。」同日补充：这条规矩「包括竞彩开的所有联赛，不止是欧战」。排在 T93 之后。

## 问题

名单里的一场比赛现在可能因为下面任何一个原因没有预测，而且往往到停售当天才被发现：

| 原因 | 最近的例子 |
| --- | --- |
| 500 网的简称对不上库内队名 | 26170 期第 11、13 场；26171 期第 5、9、10、14 场 |
| 对上了，但欧战模型只管竞彩在卖的比赛 | 26171 期同四场（T93 解决） |
| 这个联赛没有模型 | 竞彩 2026-11-25 周三001、周三002（亚冠精英）；26170 期第 1、2 场 |
| 球队在库里只有占位编号，没有名字和历史 | 26171 期第 3 场（马赛 VS 索菲亚列夫斯基） |
| 库里根本没有这场比赛，球队也不在库里 | 小联赛、杯赛 |

前两类靠 T93 和简称批准解决。后三类目前没有任何兜底：表格里是空的。

## 范围

### 一、兜底预测

1. 竞彩清单里的每一场、14 场名单里的每一场，在正式模型给不出预测时，给出一组「基准预测」。
2. 基准预测只用截点之前已知的历史赛果统计（主胜、平、客胜的历史比例；有联赛历史时用本联赛的，没有时用全库的），
   不用赔率，不用任何市场信息，不用截点之后的数据。
3. 基准预测单独成一个模型名并带版本号，与正式模型分开存、分开展示、分开计分。
4. 日报里明确标注「基准（无球队信息）」，并写明为什么没有正式预测。不得与正式预测混淆。
5. 基准预测不进任九单选和复式的主候选，不进虚拟账户和纸面串关，不适用转正规程。BET 照旧禁用。
6. 有正式预测的场次不出基准预测。

### 二、缺口清单

7. 每一班运行生成一份缺口清单（机器可读，归档到数据分支），列出当前在售的 14 场各期和今明两天竞彩里，
   每一场没有正式预测的比赛及其确切原因、需要谁做什么（批简称、补球队名字、没有模型等）。
7a. 缺口清单另附一张按联赛的汇总：竞彩在卖、但项目没有模型的联赛有哪些，各有多少场。
    所有者据此决定要不要为这些联赛建正式模型（建模型另写任务单）。
8. 日报最前面加一行覆盖情况，例如「14 场 26172 期：正式预测 12/14，基准 2/14；竞彩明日：正式 21/23，基准 2/23」。
9. 名单第一次出现的那一班就生成缺口清单，不等到停售当天。
10. job summary 里同样写一行。

### 三、文档

11. 同步 `docs/ARCHITECTURE.md`、`README.md`。

## 不做

- 不改正式模型的训练、参数、校准和选参。
- 基准预测不参与任何模型比较结论，不冒充球队模型。
- 不为没有模型的联赛新建正式模型（要建由所有者另行决定）。
- 不自动批准任何简称或球队名字；缺口清单只列出需要批什么。
- 不用赔率或任何市场信息。

## 验收标准

1. 离线测试：联赛没有模型 → 该场有基准预测，标注和原因正确；三个概率之和为 1。
2. 离线测试：球队是占位身份且没有可用模型 → 有基准预测；有正式预测的场次没有基准预测。
3. 离线测试：基准预测只用了截点之前的赛果（截点之后加入的赛果不改变结果）。
4. 离线测试：任九、复式、虚拟账户、纸面串关都不使用基准预测。
5. 离线测试：缺口清单逐场列出原因；全部有正式预测时清单为空。
6. 离线测试：日报覆盖行的数字与表格逐场一致。
7. 用 26170、26171 两期的归档数据离线重放：14 场每一场都有概率（正式或基准），缺口清单与上表的例子一致。
8. 合并后验收（Claude）：连续三期 14 场和连续三个竞彩销售日，名单里每一场都有概率；
   缺口清单在名单首次出现的那一班就已生成。
