# T85 日报保险检查做成自动的，不依赖任何 AI

来源：所有者 2026-11-25 确认的分工最终方案（`AGENTS.md`「有人停工时的替补」最后一段）。

## 问题

GitHub 的定时触发经常迟到，有时整档不触发（UTC 02:40、07:40 两档最明显）。现在靠 Claude 的定时任务
在 UTC 03:05、08:05、10:05 检查，缺了就手动补跑一次。2026-11-19 到 11-25 Claude 额度用光，
这几天没有人补跑。保险不能依赖任何 AI 的额度。

## 范围

1. 新增一个独立的小工作流 `.github/workflows/football-watchdog.yml`：
   - 自己的定时：每档之后查两次（UTC 03:05、03:35、08:05、08:35、10:05、10:35），另可手动触发；
   - 在 `ubuntu-latest` 上跑，权限只要 `actions: write` 和 `contents: read`；
   - 不接触任何 API key，不检出数据分支，不在自托管机上跑。
2. 判断逻辑写成可以离线测试的纯函数（新模块，例如 `src/zucai/watchdog.py`）。
   输入是「当前时间」和「`football-feeds.yml` 最近若干次运行的列表（含各 job 的结论）」，输出是「不动」或「补跑什么」：
   - 有运行在排队或进行中 → 不动；
   - 本档（02:40、07:40、09:40）当天 HH:30 之后已经有 schedule 运行，或已经有 `operation=daily` 的手动运行 → 不动；
   - 否则补跑：02:40、09:40 档用 `{"operation":"daily"}`，07:40 档用 `{"operation":"daily","gate":true}`；
   - 09:40 档的 schedule 运行里 predict 被跳过 → 补 `{"operation":"predict"}`；
   - GitHub 接口限流或读不到 → 不动，记日志，等下一次。
3. 补跑用 `GITHUB_TOKEN` 触发 `football-feeds.yml`（`--ref main`），每次检查最多触发一次。
4. 每次检查在 job summary 写一行大白话：查的是哪一档、结论是什么、如果补跑了原因是什么。
5. `docs/ARCHITECTURE.md` 增加一小节，`README.md` 说明这个工作流。

## 不做

- 不改 `football-feeds.yml` 的定时、并发组和任何 job。
- 不新增对体育数据源的请求；看门工作流自己不抓任何数据。
- 不用正式 key；不在开发环境触发真实工作流。
- 不删除 Claude 现有的定时检查。验收通过后是否停用，由所有者决定。
- 迟到的定时运行和补跑可能在同一档各跑一次，这是现状，不在本任务里解决。

## 验收标准

1. 离线测试覆盖「范围」第 2 点的每一条分支（用仓库里的运行列表样本，时间由参数传入）。
2. 离线测试：同一档连查两次，第一次已经补跑 → 第二次不动。
3. 工作流文件可以被正常解析，权限只有 `actions: write` 和 `contents: read`。
4. 合并后验收（Claude）：连续观察 3 天，每一档至少有一次看门运行；出现过至少一次
   「缺档 → 自动补跑 → 整条链成功」。3 天内没有缺档时照实写「没有遇到缺档，补跑这条路等真实出现时补验」。
