# T93 竞彩不卖的比赛，14 场名单对上了也要出预测（所有有模型的联赛）

来源：所有者 2026-11-26：「竞彩比赛和 14 场比赛的场次都要给得到预测，要直接把这个问题从后面出现的比赛都避开，
再也不准出现这样的问题。」同日补充：「竞彩不卖的欧战比赛也要出预测，这一条包括竞彩开的所有联赛，不止是欧战，
其他的联赛也是一样的规矩。」本任务单解决「有模型但被范围挡住」这一类缺口，兜底和预警见 T94。

## 问题

26171 期（2026-11-26 停售）14 场全是欧罗巴比赛，其中第 5、9、10、14 场竞彩不卖。所有者批准五个简称（#242）之后，
这四场对上了库内来自 `apif` 的比赛，但仍然没有预测，状态是「无模型：缺少同来源同联赛的模型」。

原因在 `src/zucai/report/batch.py` 的 `_models`：

```
if not getattr(model, "pooled", False) or source == "jc"
```

合并模型（「欧战」，覆盖欧冠、欧罗巴、欧协联）只登记 `("jc", 联赛)`，也就是只给竞彩在卖的比赛出预测。
这个条件从 T21 建立欧战合并模型时就有。T78「名单自带赛程」只放开了单联赛模型
（`src/zucai/predict/base.py` 的 `fixture_sources` 对合并模型原样返回）。

所有者 2026-11-19 已定过规矩：14 场的预测不依赖竞彩卖不卖。欧战这一块没有落实。

现有 22 个模型里，21 个是单联赛模型，1 个是合并模型（欧战）。单联赛模型已经按 T78 放开；
被挡住的是合并模型。但规矩必须对所有模型一视同仁，不能再出现「某一类模型被漏掉」的情况。

## 范围

0. 统一规矩：**任何一个有模型的联赛，14 场名单里对上了库内比赛的场次，不论竞彩卖不卖、不论比赛来自哪个来源，
   都要出预测。** 单联赛模型和合并模型同样适用，不按模型种类开例外。
1. 欧战合并模型可以为「14 场名单已经对上的库内比赛」出预测，不论这场比赛来自 `jc` 还是别的来源
   （目前是 `apif`）。只放开模型训练来源之内的来源。
2. 同一场比赛在库里有竞彩和别的来源两条记录时，仍然只用竞彩那一条出预测，不重复预测、不重复计分。
3. 名单自带赛程（T78）的规则延伸到欧战：库里没有这场比赛、竞彩也不卖，但两支球队都是库内已有的、
   在该赛事里踢过的球队时，名单这一行本身可以充当赛程。条件与 T78 相同，不新建球队，不猜名字。
4. 这样出的预测照常标明来源；球队是占位身份或没有历史时，沿用现有的「默认实力」标注和处理
   （不进任九单选和复式的主候选）。
5. 只影响 14 场名单带来的场次（`sfc_only`）。竞彩每日预测的范围不变。
6. 同步 `docs/ARCHITECTURE.md`。

## 不做

- 不改欧战模型的训练、参数、校准和选参。
- 不用赔率或任何市场信息。
- 不给联赛没有模型的比赛出预测（那是 T94）。
- 不改已冻结的预测和历史归档。

## 验收标准

1. 离线测试：欧罗巴名单里一场竞彩不卖、库内有 `apif` 比赛、两队都有历史 → 有预测，模型为欧战合并模型。
2. 离线测试：同一场比赛竞彩和 `apif` 各有一条 → 只出一条预测，用竞彩那条。
3. 离线测试：库内没有这场比赛、两队都是该赛事已有球队 → 名单自带赛程生效；有一队不是 → 不生效，原因照实写。
4. 离线测试：球队是占位身份 → 标「默认实力」，不进任九主候选。
5. 离线测试：竞彩每日预测的清单和结果与改动前逐字节相同。
5a. 离线测试（防止再漏）：遍历仓库里全部模型定义，逐个断言它的「可预测来源 × 预测联赛」都登记进了预测范围，
    没有任何一类模型被条件排除在外。以后新增模型种类时这条测试自动覆盖。
5b. 离线测试：每个单联赛模型各取一例「竞彩不卖、名单对上了库内比赛」的场次，都有预测（确认 T78 的行为没有被改坏）。
6. 现有测试全绿。
7. 合并后验收（Claude）：下一期含「竞彩不卖的欧战比赛」的 14 场名单里，这些场次有预测；
   用 26171 期的归档数据离线重放时，第 5、9、10、14 场有预测。
