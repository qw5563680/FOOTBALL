## 范围

1. **独立的实验线。** 名称 `web-research`，标注「联网研究线（实验，参考市场信息）」。不改现有模型、参数、来源、
   `forecast.json`、报告表与记分账本；它的输出不进入球队模型的输入、先验、校准或选参，也不与模型概率合并。
2. **研究对象。** 当次运行时竞彩在售、尚未开赛、且已有模型预测的比赛；按开球时间由近到远，单次运行场数有上限（配置项，默认 5）。
3. **交给大模型的材料。** 比赛身份（竞彩编号、联赛、主客队、北京开球时间）、模型给出的胜平负与比分前五与半全场概率、
   库内两队各自最近 10 场正式比赛的比分（注明来源）、研究提示词。
   提示词存入仓库（`data/prompts/web_research_v1.md`），带版本号，运行时记录其哈希；由所有者提供原文，实现方只做必要裁剪：
   删去投注动作、仓位、串关相关的要求（见「不做」），其余核验规则保留。
4. **接口适配层。** 只用 `requests`。第一个实现为 DeepSeek；适配层与提示词解耦，换一家接口只需新增一个适配实现和一项配置。
   密钥只从环境变量读取（`DEEPSEEK_API_KEY`），只存在于 GitHub Actions Secrets；日志与产物不得出现密钥。
5. **两步产出。**
   - 第一步（带联网工具）：得到带引用的研究报告原文，连同接口返回的引用列表、工具调用次数、用量，原样存档。
   - 第二步（不带联网工具）：把报告转成固定结构：数据截止时间；市场最高概率项及其概率；研究判断（主胜 / 平 / 客胜 / 无可靠倾向）
     及其概率（可为空）；依据类型；关键伤停与首发信息；主要依据与反证各若干条；引用列表。
     结构校验不通过的场次标为 `unparsed`，不猜测、不补全。
6. **程序核对与去重**（不依赖大模型自述）。
   - 比赛身份：报告里的对阵、日期、主客与目标比赛一致，否则整场标为 `identity_mismatch`。
   - 近期比赛：报告引用的两队近期比赛，与库内比分逐场对照；对不上的、库里没有的分别计数并列出；同一场比赛只计一次。
   - 赔率：报告写的竞彩赔率与库内开赛前最近一次快照对照，差异超过阈值的标出。
   - 引用：按网址去重；没有任何引用支撑的关键事实标为「无出处」。
   - 核对结果写进输出，只作告警，不改写研究判断。
7. **冻结。** 开赛前写入独立文件（与 `forecast.json` 同批次目录下的 `web_research.json` 与原文文件），记录生成时间、
   提示词版本与哈希、接口与模型名、用量与费用估算。已开赛的比赛不生成、不补写。同一场比赛在不同运行中的多份结果都保留，不覆盖。
8. **展示。** 每日摘要新增一节「联网研究线（实验）」：每场列出市场最高概率项、研究判断、一两句主要依据、核对告警数。
   不出现 BET / WATCH / PASS、仓位、入场价。
9. **计分。** 记分板单独统计这条线：研究判断的覆盖率与命中率分开报；给出概率的场次按 Log Loss 与 Brier 计分；
   与同一批比赛上的赔率基准、纯模型按比赛编号配对比较。「无可靠倾向」不算命中也不算失误。计分只从本单合并后的冻结结果起算。
10. **入口与花费上限。** 新增审查者触发的 `operation=web-research`；并入每日链的开关默认关闭，由所有者批准后再开。
    每次运行有场数上限与费用上限（配置项），到上限即停并把状态记为 `partial`；接口报错或超时的场次标为 `failed`，不重试到超限。

## 验收

1. 既有不变：同一归档副本、固定时刻重放，训练行数、模型内容、`forecast.json`、报告表、记分账本与评分文件逐项不变；
   这条线关闭时每日链的全部产物与合并前逐字节相同。
2. 离线测试只用 `data/fixtures/`：裁剪后的接口响应样本覆盖正常、无引用、结构不合格、身份不符、接口报错、到达费用上限六种情形；
   测试不得真实联网，不得出现真实密钥。
3. 核对逻辑有针对性的测试：引用比分与库内不符、重复引用同一场、赔率差异超阈值，都能被标出。
4. 真实试跑（审查者执行，需所有者先配置密钥）：`operation=web-research` 跑 2 至 3 场，记录每场的工具调用次数、token 用量、
   实际费用与核对告警；据此回填 `docs/DATA_SOURCES.md` 里 DeepSeek 一节（接口、工具名、支持的模型、计费、`safety_check` 的实际要求）。
5. 每日摘要与记分板里这条线单列，标注「实验」；BET 保持禁用。
6. 全量 `pytest -q`、`ruff check`、`ruff format --check` 通过；README 补一行用法；ARCHITECTURE 补产物位置；`reports/` 新增不超过 200 KB。

## 失败标准（事前写明）

- 积累到至少 100 场有明确研究判断并已完赛的比赛后评估：若研究判断给出的概率在同批比赛上 Log Loss 不低于赔率基准，
  且首选命中率不高于赔率首选，则结论为「没有独立于市场的增量」，这条线只保留为信息摘要或关停，由所有者决定。
- 试跑或运行中，「引用比分与库内不符」的场次占比超过两成，判定该接口的研究结果不可靠，暂停并换接口重评。
- 单场实际费用超过所有者设定上限的两倍，暂停并重新核算。

## 不做

- 不把联网研究线的任何输出（含赔率、新闻、研究判断）送进球队模型；不合并概率；不改既有模型。
- 不给下注建议、仓位、串关；不自动下注；BET 保持禁用。
- 不用浏览器自动化，不引入重型依赖；不自行抓取体育网站，联网只通过接口自带的工具完成。
- 开发环境不用正式密钥发真实请求；不用合成样本冒充实测。
- 不回填本单合并之前的比赛。
