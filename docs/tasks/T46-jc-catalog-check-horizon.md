# T46 · 竞彩清单逐号核对：预测窗口之外的场次不得标「确定漏了」（T39 小修）

## 背景
2026-11-06 11:47（北京）日报 run 42157651542-1 的「竞彩完整清单逐号核对」写道：

> 缺 周六022（2026-11-07，帕尔马 VS 博洛尼亚）：确定漏了；入库但无赛前预测（晚班或后续同步已入库，但无可查的赛前预测）。

周六022–028 共 7 场同样措辞。核对数据分支：这 7 场的 `kickoff_utc` 为 2026-11-07 17:00–19:45 UTC，即北京 **11-08** 01:00–03:45；
竞彩清单的 `business_date`（营业日）是 11-07，而本次预测只覆盖北京 11-06（今日）与 11-07（明日）两批，11-08 批次要到明天才生成。
它们不是「漏了」，而是**尚未进入预测窗口**。把这种情况写成「确定漏了」违反 T39 对缺号分类的要求（确定漏了 / 原因未查明 要有证据），
会让所有者误以为系统漏预测。T39 的「上周三 012 光看 001 到 011 发现不了」要解决的是真漏号，不是营业日跨自然日的时差。

## 范围（2026-11-06 所有者澄清）
1. `digest_views` / `digest_context` 的逐号核对按真实北京开球日判断，不能用编号日或营业日代替。
   计划范围是日报生成时北京时间今日 + 明日；成功范围另读截点前 prematch 批次的
   `input.kickoff_date_beijing`。整天批次失败/缺失不能缩小计划范围，须明示该日尚无成功批次。
2. 窗口内或早于窗口且确实缺预测，按证据标「确定漏了」与是否查明原因。晚于计划窗口标
   「尚未进入预测窗口」，排除漏预测数；开球时间缺失/无法解析时标「开球时间缺失，无法判断窗口」，不猜。
3. 首行互斥计数：确定漏了（原因已知）、原因未查明、尚未进入预测窗口、无法判断窗口。
   漏预测合计仅前两类；明细同时保留「确定漏了」这一缺失事实和未知原因的区分。
4. 未来场次列北京时间开球日期/时间及预计进入预测范围日期（开球日前一天）；说明以实际批次为准，
   不写一律「下一班预测」，不保证定时任务准点。
5. README 同步；不改数据库结构和预测范围。
