# T46 · 竞彩清单逐号核对：预测窗口之外的场次不得标「确定漏了」（T39 小修）

## 背景
2026-11-06 11:47（北京）日报 run 42157651542-1 的「竞彩完整清单逐号核对」写道：

> 缺 周六022（2026-11-07，帕尔马 VS 博洛尼亚）：确定漏了；入库但无赛前预测（晚班或后续同步已入库，但无可查的赛前预测）。

周六022–028 共 7 场同样措辞。核对数据分支：这 7 场的 `kickoff_utc` 为 2026-11-07 17:00–19:45 UTC，即北京 **11-08** 01:00–03:45；
竞彩清单的 `business_date`（营业日）是 11-07，而本次预测只覆盖北京 11-06（今日）与 11-07（明日）两批，11-08 批次要到明天才生成。
它们不是「漏了」，而是**尚未进入预测窗口**。把这种情况写成「确定漏了」违反 T39 对缺号分类的要求（确定漏了 / 原因未查明 要有证据），
会让所有者误以为系统漏预测。T39 的「上周三 012 光看 001 到 011 发现不了」要解决的是真漏号，不是营业日跨自然日的时差。

## 范围
1. `digest_views` / `digest_context` 的逐号核对：对每条清单条目按 **北京开球日** 判断是否落在本版预测窗口（已冻结批次的 `kickoff_date_beijing` 集合）内：
   - 在窗口内且无赛前预测 → 维持现有「确定漏了 / 原因未查明」分类与措辞；
   - 开球日晚于窗口（如营业日 11-07、开球北京 11-08）→ 新分类「尚未进入预测窗口（北京 MM-DD 开球，下一班预测）」，不计入「漏号」计数；
   - 开球日早于窗口且无预测 → 维持「确定漏了」。
2. 小节首行给出三类计数（漏号 / 原因未查明 / 尚未进入窗口），核对范围说明保留。
3. 若清单行缺 `kickoff_utc`，仍按原逻辑处理并写明「开球时间缺失，无法判断窗口」。
4. 文档：README 日报说明一句；ARCHITECTURE 不涉及表结构，不改。

## 不做
- 不改预测窗口（仍是今日 + 明日两批）；不改清单采集、T42 分片、T39 其他小节；不改记分板。

## 测试（离线）
- 用 `data/fixtures/t39` 的清单样本构造：营业日 D 内一场开球北京 D+1 → 「尚未进入预测窗口」；同营业日另一场开球 D 且无预测 → 「确定漏了」；缺开球时间 → 原逻辑。
- 现有 T39 逐号核对用例不变。

## 验收标准
