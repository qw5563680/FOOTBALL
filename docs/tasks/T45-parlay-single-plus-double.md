## 范围
### 1. 单选场怎么选（所有者第 1 条）
从**本批已经研究过、发报时尚未开球**的比赛里选：同一 `batch_id` 内 `status=predicted` 且 `kickoff_utc` 晚于本次冻结时刻的 jc 比赛，只用竞彩普通胜平负（had），主队视角、90 分钟含补时结算。
- 原研究唯一倾向 = 冻结行 `model_probabilities` 的最高项；单选项必须等于它。若 `experimental.json` 同场有可用 `model_probabilities`，其最高项也须一致，否则该场不能当单选（进诊断日志）。
- 方向脆弱不当单选：`top1 − top2 < single_direction_gap`（配置，默认 0.10，写进文档并可按实验改）；或 T38 伤停截点前最新捕获缺失 / 该队 `confirmed_injured_out` 未知时标「关键反证未解决」。所有者的例子：原判主胜，但主力门将是否出场就足以改变判断，这场先跳过。第一版这类只进诊断日志，不进主候选。
- 单选项的竞彩 SP **< 1.20 直接排除；= 1.20 只通过价格下限**，仍标「继续审核」。不得借双选腿拉高乘积绕过，不得把第二热门升为单选只为过门槛。
- 不设单选胜率百分数门槛。每个单选列出支持、反证、可能改变方向的条件（能从冻结行与伤停表读出的部分），SP 与概率带版本（`model_version`、`market.snapshot_utc`）。

### 2. 双选场怎么选（第 2 条）
- 对候选场逐一算三种搭配：胜＋平、胜＋负、平＋负。每种写清覆盖的两项、**放掉的第三项及其模型概率**。例：主胜 45%、平 20%、客胜 35% → 覆盖最高是「胜＋负」，放掉平局 20%。
- 两项必须来自同一场、同一普通胜平负、同一份概率分布；不得混用让球（hhad）或境外「双重机会」报价。
- 默认取覆盖概率最高的搭配；禁止固定「强队＋防平」、固定排除平局、为高 SP 换掉概率更高的一项。
- 方向脆弱：`p(放掉项) ≥ p(覆盖中较小项) − double_fragile_gap`（配置，默认 0.05）时标脆弱，只作参考不进主候选。
- 双选两项**不套**单选的 1.20 下限。没有可靠完整概率的场不报模型覆盖率。赛后只算票面覆盖，不能补记原研究猜对。

### 3. 多组怎么分散（第 3 条）
- 同一轮主展示的所有组中，**每场比赛最多出现一次、每支球队最多出现一次**，四支参赛队全部占用（含作为对手、被选输的球队）。第 1 组用了国际米兰，第 2 组选国米输、把国米放进双选、或网站写「国际米兰」而非「国米」，都算重复。
- 用统一 `match_id` 与球队 ID（`matches.home_team_id/away_team_id`）核对，不按简称；同一组两注共享两场是复式票本身，去重只针对不同组。
- 默认 3 组（需 6 场、12 支不同球队），最多 5 组；候选不够就给 0–2 组等实际数量，**不为凑数牺牲资格**。
- 重跑同批次：保留旧版、标明哪组被替换、只认一个当前版本；已计入纸面账的组锁定，重跑不重复建票、不绕开占用。不把「跨组不重球队」误写成某队整季只能出现一次。

### 4. 怎么排第一（第 4 条）
- 枚举：同一证据等级内，所有有序配对 (A 单选场, B 双选场)，A≠B，A 的 3 个单选项 × B 的 3 种双选搭配 = 9 种，共 9×N×(N−1) 种安排；先按第 1、2 节资格过滤，保留过滤前后数量。
- 整组覆盖概率 = q1 + q2（见第 5 节），按**原精度**降序；完全同分用稳定的比赛 ID 与选项顺序（主 / 平 / 客）。依次挑不撞球队、不撞比赛的组：每选出一组登记其两场与四支球队，再检查后续候选。这是贪心筛法，**不得说成对所有组的总命中率做了优化**。
- 另列「整组盈利概率最高」的组。
- 榜单分开：球队模型主榜（P2 实验 / 前瞻已验证 / 历史门槛通过各自标注）、实验模型榜（如 dc-sot-v1）、市场参考榜（只有赔率时，用去水市场概率，**只能单列为市场参考，不填进球队模型榜**，不把跨榜重合当新增分散机会）。正式模型缺失的场不得拿市场概率冒充预测。

### 5. 怎么算中了、怎么算赚钱（第 5 条）
A 单选 α，B 双选 β、γ，展开为两注基础注「Aα×Bβ」「Aα×Bγ」，1 倍、每注 2 元、整组本金 4 元，默认等额；两场都有效时最多中一注。
- 有联合模型时记两分支联合概率 q1、q2；只有单场概率时明示「跨场独立近似」：q1 = p(Aα)×p(Bβ)，q2 = p(Aα)×p(Bγ)。
- 整组覆盖概率 = q1 + q2（赛前估计；赛后实际命中率用已结组数另算）。
- 两注奖金各用自己的两个 SP：奖金 = 2 × SP_A × SP_B，按可核实规则取位（取位方式与官方依据写进配置与 `docs/DATA_SOURCES.md`，未核实前标「未核实」；参考所有者提供的[福建体彩网胜平负规则](https://www.fjtc.com.cn/2024-04/01/content_31550872.htm)），不能合成「一个组合赔率」。
- 三行分支表：第一注中 q1、第二注中 q2、都不中 1−q1−q2；每行写概率、整组本金 4、奖金、净收益（奖金 − 4）。
- 整组盈利概率 = 净收益**严格大于 0** 的分支概率之和；回本单列。税前 EV = q1×G1 + q2×G2 − 4，预计 ROI = EV ÷ 4。有税费 / 规则差异时按各分支实际净收益核算，不明就标未核实。官方无效场、取消等走异常结算，不猜退款规则（沿用现有「待结不猜」原则）。
- 「中了其中一注仍亏」要如实展示。最终分别给：覆盖最高组、盈利概率最高组、有没有可执行价值（未知写未知）。**不把各组概率相加算「至少中一组」。**

**固定验收例（假设数据）**：A 单选模型概率 60%、SP 1.25；B 双选两项 50% / 30%，SP 1.44 / 3.20，第三项 20%；独立、正常结算、每注 2 元、不计税费。
| 分支 | 概率 | 奖金 | 扣 4 元后 |
| --- | ---: | ---: | ---: |
| 第一注中 | 30% | 3.60 | −0.40 |
| 第二注中 | 18% | 8.00 | +4.00 |
| 都不中 | 52% | 0 | −4.00 |
覆盖概率 48%，盈利概率 18%，税前 EV −1.48 元，预计 ROI −37%。程序必须把 48% 与 18% 分别算对，并能测出「命中但亏损」。

### 6. 输出、冻结、账本与复盘
- 新模块 `src/zucai/parlay/single_double.py`（枚举、过滤、贪心分散、现金流）与 `scoreboard` 的新虚拟账户 **F「单选＋双选二串一」**：独立 `rule="single_plus_double_v1"`，每批每档最多 `max_groups`（默认 3，上限 5）组，每组两张 2 元注单共 4 元；注单保存批次、两场 `match_id`、四支球队 ID、单 / 双选项、三个 SP 与 `snapshot_utc`、未四舍五入的概率、`model_version`、证据等级、筛选范围（过滤前后数量）、两分支现金流；结算只填结算字段，两注分开结、组级另汇总。
  F 对 `p2_ready=false` 的「P2 实验」概率也开纸面组（与 A–E 不同），但每张注单与统计都带 `p2_label`，报表按证据等级分列，不与 D 合并。
- 冻结文件：`forecasts/<北京开球日>/<run>/parlay_sd.json`（主表 + 诊断 + 筛选范围 + 市场参考榜），SHA256 进 `forecast_manifest.json`；原四件套与 `experimental.json` 字节不变。可评分的组必须在最早一场开球前冻结；要宣称「当时可执行」还须两场共同销售窗口未关且留下时间证据——现有数据只有 `sellStatus/matchStatus/lastUpdateTime`（jc 清单）与 `market.snapshot_utc`，没有官方停售时刻字段，因此第一版一律标「可执行性未核实」，并在 `collect_jc` 顺手把 sporttery JSON 里若存在的停售字段存入清单（没有就不造）。
- 日报新小节「二串一候选（单选＋双选，纸面）」：主表并列原单场判断、模型三项概率、市场参考、单 / 双选、放掉的结果及概率、两注展开、三个 SP 与时间、组覆盖概率、整组盈利概率、EV、缺口与动作；附最容易同时击穿的条件；合格组为零就写零。沿用 T39 的「本日第 k 次更新 / 较上一版」机制。
- 赛后复盘分开统计：原单选判断命中率、两条基础注各自结果、已结合规组实际覆盖率、整组盈利率、纸面投入 / 盈亏 / ROI；异常、待结、事后重建（`replayed=true`）分别标注；未出票不计实投业绩。
- 文档：README 账户表加 F 与新小节说明、ARCHITECTURE 数据模型 / 冻结文件表加 `parlay_sd.json` 与账本字段、`docs/DATA_SOURCES.md` 记取位规则依据与停售字段结论。

## 不做
- 不改 A–E 任何账户、不改 D 的规则与历史；不改正式或实验模型；赔率不进模型概率、不进校准、不进选参。
- 不用让球、境外双重机会、海外赔率冒充官方 SP；不读事后收盘价。
- 不实现真实下单、不解除 BET 禁用、不写「可实战」。若未来允许实战，仍按原规则整批最多 1 组并重新核实过关资格、共同销售窗口、四队正式首发、独立概率证据与保守净 EV；首发公布晚于较早出票截止即不合格；只有临场能解决并给出核对时间的问题才标 WATCH，否则 PASS。
- 不做「至少中一组」的跨组合并概率；不把贪心筛法说成全局最优。

## 测试（离线，fixtures）
- 固定验收例：q1=0.30、q2=0.18、覆盖 0.48、盈利 0.18、G1=3.60、G2=8.00、EV=−1.48、ROI=−0.37；「第一注中」净收益 −0.40 记为亏。
- 单选 SP 1.19 排除、1.20 通过价格下限且标继续审核；双选含 <1.20 的选项不因此剔除。
- 独立模型最高项不一致 → 不当单选；`top1−top2` 低于阈值 → 诊断日志。
- 三种双选搭配全部列出，放掉项与概率正确；脆弱判定正确。
- 去重：第 2 组出现第 1 组任一球队 ID（含作对手、换简称「国际米兰 / 国米」同一 ID）→ 跳过；3 组 = 6 场 12 队；候选不够允许 0–2 组。
- 排序：按 q1+q2 原精度降序，同分按稳定 ID 与主 / 平 / 客顺序；盈利概率最高组另列。
- 仅不支持单关而支持 2 串 1 的场可入过关审核（用 jc 清单 `single/allUp` 字段）；比赛已开始 / 结束 / 取消 / 停售 / 身份冲突 → 排除当前执行候选，资格待核只单列参考。
- 纯市场输入只能出市场参考榜，模型榜为空。
- 账本：同批重跑不重复记账、已记账组锁定；两注分开结算，组级覆盖 / 盈利分别统计；取消场保持待结。
- 冻结：`parlay_sd.json` SHA 进 manifest，原文件字节不变。

## 验收标准
- 所有者原话：**少给一组可以，重复压同一支球队不行；模型给不出可靠概率就留空；纸面中了但整组亏钱，就按亏钱记。**
- 固定验收例的 48% / 18% / −1.48 / −37% 全部复现；上述边界用例全绿。
- 真实验收（审查者）：合入后一次早班 run 的 `parlay_sd.json` 与日报小节出现，候选数、过滤前后范围、四队占用可逐条核对；账户 F 在次日结算中两注分开、组级分开。
- 与现有实验线的关系：本任务是纸面玩法层，不新增模型实验线（当前并行实验线 dc-sot-v1 / dc-xg-v1 / T38 伤停不变）。
