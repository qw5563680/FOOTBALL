# T100 第四条实验线：跨联赛的球队评分（只用赛果，不用市场信息）

来源：所有者 2026-11-27「乙、丙都写」里的丙。提案与失败标准见 `docs/proposals/2026-11-27-cross-league-rating.md`，开工前先读。

## 现状（main `ff1a884`）

- 正式球队模型（`dixon-coles`）每个联赛单独训练。球队在本联赛没有历史时，用「本联赛最弱四分之一球队打折」的默认强度
  （`src/zucai/predict/dixon_coles.py` 的 `weakest_quartile_half_shrinkage`，输出里带 `unknown_team_prior` 标记）。
- 并行实验线在 `src/zucai/predict/experiments/parallel.py` 注册，现有 `dc-sot-v1`、`dc-xg-v1`；另有融合线 `team-market-blend-v1`。
  共三条在跑，上限四条。
- 实验线的采用规则是 `src/zucai/scoreboard/experimental.py` 的 `t34a-adoption-v1`（共同样本 ≥ 200 等），现有两条线按联赛分组计算，
  到 2026-11-27 各组共同样本只有 0 到 10 场。
- 球队表是全库一张（`teams`，名称唯一），同一支球队在不同联赛原则上是同一行；已知例外是还挂在临时身份下的历史
  （身份合并审计里 17 行「目标联赛正式别名未传播」：德乙 8、荷乙 9）。

## 范围

1. **先数清楚身份缺口（离线，写进 PR）。** 对每个有正式模型的联赛，统计最近三个赛季里升级、降级进来的球队，
   有多少能在球队表里接上它在另一级联赛的历史，有多少接不上（列出球队和原因）。只统计、不修补。
2. **先登记协议，再跑回溯。** 新增 `docs/experiments/T100-cross-league-rating-protocol.md`，写明并记下哈希：
   - 评分怎么更新：每支球队一个分数；每场比赛按「实际结果减去赛前预期」加减，净胜球越大幅度越大；主场有固定加分；
     首次出现的球队取它首场比赛所在赛事里、当时已有评分球队中最低四分之一的平均值，该赛事还没有球队有评分时取全局初始值；
   - 分差怎么换成胜平负概率：有序三分类（主胜/平/客胜）的对应关系，只用赛果拟合；
   - 候选参数（更新幅度、主场加分等）的取值表，和选参办法：只用 2026-07-01 之前开赛的比赛，按时间先后滚动评估 Log Loss；
   - 评估口径：所有联赛合并成一组；另按联赛、按「正式模型用了默认强度的比赛」分别列描述性数字；
   - 提案第 5 节的四条失败标准，原样写入。
   协议提交之后才跑第一次回溯；回溯失败或重跑，都在 PR 上登记原因。
3. **回溯。** 参数冻结后，在 2026-07-01 之后已有赛果的比赛上，与正式模型的历史回放按比赛编号逐场配对，
   报告 Log Loss、Brier、校准、共同样本数，以及上面两类描述性分组。
   评分模型的 Log Loss 比正式模型同场高出 0.015 以上时，**到此为止**：PR 只交协议和回溯报告，不注册实验线，在 PR 里写明。
4. **注册为第四条并行实验线**（回溯过了第 3 点才做）。模型名 `elo-global-v1`，版本号单列；与现有实验线同样标
   `model_type=TEAM`、「P2 实验」、`bet_allowed=false`、`p2_ready=false`，`training_availability_mode=backfill_replay`、
   `target_availability_mode=strict_capture_time`。和正式模型同批、同场、同截点冻结。
   - 只给正式模型有预测的比赛出预测；有一队没有评分时写「未生成」并写明原因，不用别的东西顶替。
   - 评分只读截点之前可知的赛果，判断规则沿用正式模型现有的那一套。
5. **成绩单。** 新增一组「跨联赛评分 对 正式模型」的同批比较：所有联赛合并成一组计算采用规则，另列按联赛和「默认强度」子样本的描述性数字。
   再加一行「各半平均」对照（正式模型与评分模型概率各占一半），只在计分时计算，写明「对照，不是一条实验线」。
   现有两条实验线的分组和数字不变。
6. **日报。** 实验栏多一条，写法与现有实验线一致。不改正式预测、爆冷、任九、14 场、虚拟账户和纸面串关。
7. 回溯报告按任务规则第 8 条放：`reports/` 只放 README 和 SHA256 清单，逐场明细放数据分支或 Release 附件。
   `README.md`、`docs/ARCHITECTURE.md` 同步；实验线清单更新为四条。

## 不做

- 不用赔率、收盘价、投注比例或任何市场信息，训练、选参、校准、评估对手都不用。评估对手只有正式球队模型。
- 不改正式模型的参数、来源和输出；评分不作为正式模型的输入或先验。
- 不给没有正式模型的赛事出预测（那是 T62 的事）。回溯报告里顺带数一数这类比赛有多少场两队都有评分，只报数。
- 不修补球队身份，不合并球队，不批准任何队名。接不上的历史照实统计。
- 不新增数据来源和接口请求；不引入重型依赖。
- 不进虚拟账户和纸面串关；不适用自动转正，达到采用门槛只提交所有者决定。
- 「各半平均」不发布、不进日报、不存为预测行。
- 不在看到 2026-07-01 之后的结果后回头改参数或改评估口径。确需修改时停下来在 PR 里说明，由所有者决定。

## 验收标准

1. 离线测试：评分更新只用截点之前可知的赛果；把一场截点之后的赛果放进样本，评分与预测不变。
2. 离线测试：同样的输入重复运行，评分快照和预测逐字节相同；模块的输入白名单里没有任何市场字段（参照 `parallel.py` 的写法）。
3. 离线测试：首次出现的球队按协议取初始值；一队没有评分时该场「未生成」并带原因。
4. 离线测试：成绩单把所有联赛合并成一组计算这条线的采用规则；现有两条实验线、融合线、正式模型的数字逐项不变。
5. 离线测试：「各半平均」只出现在成绩单的对照行，不出现在预测文件、日报和账本里。
6. 协议文件的哈希写在 PR 和回溯报告里；协议的提交时间早于第一次回溯的运行时间，PR 里给出两者。
7. 合并后验收（Claude）：
   - 第一班正式运行：日报实验栏出现这条线，正式预测、爆冷、任九、14 场、账户与上一班口径一致；
     预测文件里它的场次数与正式模型一致或写明缺的原因；
   - 之后每满 100 场共同样本，在任务表更新一次进度；满 300 场和 600 场时对照失败标准给所有者结论。
