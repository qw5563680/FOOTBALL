## 范围

1. **市场参考概率。** 取同一家运营商、同一条快照里完整的主胜、平、客胜三项十进制赔率：
   各项取倒数得原始隐含概率，三项之和为 S；去水概率为各项除以 S；理论返还率为 1/S。
   三项缺任何一项就不生成，不用别的快照或别家的报价补齐。计算方法带版本号。
2. **用哪一条报价。** 取项目采集时间不晚于该批预测截点的最后一条完整快照。
   每场记录写明：实际运营商、数据供应商、来源给出的报价时间（来源不提供就写「来源未提供」，不用采集时间顶替）、
   项目采集时间、被采用快照的标识、三项赔率原值、去水概率、返还率、方法版本。
3. **首次采集与初盘。** 项目第一次抓到的那条标「首次采集」，与「预测采用」的那条分别记录；
   只有来源明确标为初盘的报价才写「初盘」。目前没有这样的来源，这一项照实显示「来源未提供初盘」。
   只有两条快照时只描述这两点之间的变化，不画中间走势。
4. **日报三栏。** 每日摘要的比赛表改为三栏并排：「球队模型」「市场参考」「球队＋市场（实验）」，各列主胜、平、客胜概率。
   - 球队模型没有结果：写「球队模型未生成」并写原因（沿用预测记录里已有的原因字段）。此时有赔率也只填市场参考栏。
   - 没有合格快照：市场参考栏写「市场参考未生成」并写原因（未开售、报价不完整、采集晚于截点等）。
   - 「球队＋市场（实验）」栏在 T72 合并之前一律写「未生成（融合实验尚未上线）」。
   - 表下用一句话标出球队模型与市场参考差距最大的方向及差值；不解释原因，不写「诱盘」「资金流向」之类的推断。
5. **状态表。** 日报附一张小表，逐项写明上面「现状」里各类信息当天的状态：
   已真实接通／可计算／权限不足／来源不提供／尚未实现。拿不到的不留空、不写 0。
6. **一场真实比赛的样例**（本单的首要交付物）。提供一个只读命令：输入归档与比赛编号，输出该场的完整出处页，包含：
   每一条已采集的胜平负快照（运营商、项目采集时间、来源报价时间、三项赔率），其中哪条是首次采集、哪条被预测采用；
   球队模型概率与市场参考概率并排；必发一栏逐字段列出成交价、成交量、盘口深度各自的状态。
   样例由审查者在真实归档上执行该命令生成并贴到 PR；实现者只用离线样本自测。样例放 `reports/`，不超过 200 KB。
7. **记分板。** 在现有「模型对赔率」对照之外，列出每批预测里市场参考栏缺了多少场、因为什么缺。

## 验收

1. 既有不变：同一归档副本、固定时刻重放，训练行数、模型内容、`forecast.json` 里的球队模型概率与比分矩阵、报告表既有列、
   记分账本与评分文件逐项不变。
2. 完整三项去水后合计为 1（浮点误差内）；缺一项时不生成；采集时间晚于截点的快照不会被采用；重复采集不重复计数。
3. 首次采集不会被标成初盘；来源未给报价时间时不会出现采集时间冒充的情况。
4. 球队模型缺失、市场缺失、两者都缺三种情形，日报三栏的文字与本单第 4 条一致。
5. 审查者在真实归档上生成一场未开赛比赛的样例，所有者能从样例里直接读出：报价来自哪家、项目何时拿到、预测采用了哪一条。
6. 全量 `pytest -q`、`ruff check src tests examples`、`ruff format --check src tests` 通过；README 补一行用法；
   预测记录字段有变化时同步 `docs/ARCHITECTURE.md`。

## 不做

- 不做融合，不改球队模型的任何输入、参数、校准。
- 不接新的数据源，不发新的接口请求；亚洲让球、大小球、必发、多公司即时赔率由审查者先探测（见下）。
- 不做凯利指数、不做资金流判断、不给下注建议；BET 保持禁用。
- 不回填本单合并之前的预测批次。

## 审查者负责的探测（不属于实现者范围）

沿用现有套餐，不新购服务。逐项经 Actions 探测并把真实结论回填 `docs/DATA_SOURCES.md`，每一项都需所有者事先同意：

- API-Football 现有套餐的赔率接口：能否取得目标赛事、有哪些运营商、是否有亚洲让球与大小球、历史保留多久、每次调用耗多少配额。
- football-data.co.uk 的历史表里亚洲让球与大小球收盘列的覆盖情况（已有文件，离线核对即可）。
- 必发：先确认是否存在现有套餐内、且条款允许的取得方式；成交量与盘口深度分别核验。不存在就写「权限不足」，不绕过登录、地域或订阅限制。
