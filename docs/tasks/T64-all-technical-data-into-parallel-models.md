# T64 接口的全部技术数据进入模型训练：扩到全部联赛，并增设「全数据」实验模型

来源：所有者 2026-11-14 指示「必须把所有接口的数据都给到模型去训练」。
比分类数据由 T60–T63 负责进入正式模型；本单负责比分以外的数据（射门、射正、xG、控球、角球、
红黄牌、事件、阵容、伤停）。依赖 T61（联赛对照与下载）。
分支 `codex/T64-all-technical-data-into-parallel-models`，PR 标题以 `T64:` 开头。

## 现状（审查者核对，数据分支 `1657093`）

- 技术数据已在采集：统计行 448,392 条（回填 442,020、当日捕获 6,372），伤停 101,462 条
  （`state/stats_coverage.json`，原件在 Release `stats-raw-*`）。
- 已有两条实验线每天与正式模型并行预测同一批比赛（T33、T34a）：
  `dc-sot-v1`（射正强度，fd 九联赛）与 `dc-xg-v1`（xG 强度，apif）。
- 证据现状：
  - T33 历史回放两条线都略差于正式模型（fd 共同样本 LL 差 +0.006 [−0.004, +0.016]，
    apif +0.011 [−0.004, +0.027]），区间都跨 0。
  - 前瞻并行：记分板 `experiments` 里每个联赛的共同样本只有 0–10 场，采用规则要求每联赛 200 场，
    全部为「证据不足，保持 P2 实验」。
- 尚未做的：T34b（候选二：正式模型概率 + 技术特征的校准层）没有实现；T38 伤停特征只有离线一轮；
  阵容、事件没有进入任何模型；实验线只覆盖少数大联赛。

## 范围

1. 采集扩面：技术数据的回填与每日捕获扩到 T61 对照表中接口有统计覆盖的全部联赛与赛事，
   先总表第 1、2、3 组的联赛，再杯赛与洲际赛。回填由审查者按配额分批触发
   （每场每个端点一次请求，须给出各批请求量估算并为每日采集留足余量）。
   接口没有的字段如实记缺失，不用别的字段冒充。
2. 现有两条实验线扩面：`dc-sot-v1`、`dc-xg-v1` 的并行输出扩到所有具备所需统计的联赛，
   协议、参数化与采用规则不变。
3. 第三条实验线「全数据模型」：实现 T34b 的候选二校准层，并把输入扩为接口提供的全部赛前可知
   技术特征（射正与 xG 的攻防差、伤停人数差、上一场首发延续、休息天数差、红牌标记等）。
   协议与特征清单先于任何结果提交；带「只做重校准、不含技术特征」的消融；
   通过离线协议后接入每日并行输出。并行实验线合计三条，不再多开。
4. 每一类数据「赛前何时可知」沿用 T31、T38 的口径：只用真实捕获时间早于开球的版本；
   回填数据只能用于训练回放并如实标注，不能冒充前瞻证据。
5. 日报与记分板：实验线照常分列，标签固定「P2 实验」，直到满足采用规则。

## 需要所有者决定的一件事（本单不擅自改）

现行采用规则是每个联赛单独攒够 200 场共同样本才比较，按现在的速度要好几个月。
可选做法是事前登记一条「跨联赛合并评估」规则（同一批比赛按 ID 配对、Log Loss 主指标、
周整块自助区间），几周内就能得出第一轮结论。是否改规则由所有者决定；
未决定前沿用现行规则，实验模型不得进入正式模型位置。

## 验收

1. 协议先行：T34b 设计文档与评估协议 JSON 在结果之前提交；特征白名单写死，其余字段不暗中入模。
2. 离线：同一数据快照上审查者独立复算，配对差与区间一致（容差 1e-4）；允许结论为「无改善」。
3. 泄漏与红线：训练、特征、校准、选参不读赔率；特征截点为 `min(as_of, kickoff)`；
   新增测试覆盖「捕获晚于开球的技术数据被拒」「缺失不填 0」「消融与全模型共用样本掩码」。
4. 线上（审查者执行）：合并后连续三次每日链路成功；三条实验线对其覆盖联赛的在售场次给出并行预测
   并进入记分板分列；正式模型的预测与此前逐字节一致。
5. 交付覆盖表：每个联赛、每类技术数据的入库场数、赛季范围、缺失原因。
6. 全量 pytest、ruff 通过；测试只用 `data/fixtures/`；大文件走 Release；`reports/` ≤ 200 KB；
   README、ARCHITECTURE、DATA_SOURCES 同步。

## 不做

- 赔率与任何市场信息不进入模型输入、先验、校准、选参。这是所有者确认过的仓库红线，
  「所有接口的数据」不包含赔率。
- 不在满足采用规则之前把实验模型换进正式模型位置；不改 `params.json` 的 P2 门槛；BET 禁用。
- 不回写冻结预测、旧报告、旧评分、旧账本；不重写 T33、T38 第一轮的产物与结论。
- 不引入深度学习框架或其他重型依赖。
