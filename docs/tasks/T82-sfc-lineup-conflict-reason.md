# T82 14 场官方对阵和 500 网对不上时，日报写明原因

来源：所有者 2026-11-25「对不上要告诉我原因」；
`docs/reviews/2026-11-25-codex-217-224-audit.md` 第 3 条。

## 问题

T79 之后，官方公告与 500 网的场序或主客队冲突时，`src/zucai/sfc_digest.py` 的 `_issue_lines`
会把可用的报告清空（`lineup_conflict` 为真时 `choices = []`）。日报里只剩「官方核对：冲突」和
「核对差异 N 项，逐场记录见 <链接>」，单选、复式、任九都不展示。所有者不知道是哪一场、差在哪里。

任九一节此时显示的是「未确认报告在截止前发布，本期不展示任九方案」（`src/zucai/report/sfc.py` 的
`pick_nine_lines`），这句话说的不是真实原因。

差异明细其实已经在核对结果里：`src/zucai/sfc_verification.py` 写入的 `differences`，每条有
`seq`、`field`、`official`、`provider`、`reason`，场序或主客不同的还有 `official_seq`、`official_side`。

## 范围

1. 冲突时，在 14 场一节把每一条冲突（`status == "conflict"`）用大白话列出来，一条一行。例如：
   「第 7 场主队：官方公告写『A』，500 网写『B』；公告里这支队在第 9 场客队。」
   停售时间冲突同样写明两边各是什么时间（北京时间）。
2. 紧接着写明后果：「因此本期不展示单选、复式和任九，等两边核对一致后恢复。」
3. 任九一节在这种情况下写同一个原因，不再显示「未确认报告在截止前发布」。
4. 只是「待核」（`status == "pending"`）的差异保持现在的展示，不算冲突。
5. 冲突解除后的下一版日报自动恢复展示，不需要人工操作。
6. 本任务只补原因。「冲突时不出推荐」这条规则不变。

## 不做

- 不改核对规则（`sfc_verification.py` 的判定）和官方公告的采集。
- 不改冻结报告的内容和历史归档。
- 不用 500 网的对阵顶替官方对阵去出推荐。

## 验收标准

1. 离线测试（用 `data/fixtures/` 里现有的官方公告样本或其裁剪）：主客颠倒 → 日报出现逐条冲突说明
   （场序、官方写的名字、500 网写的名字）和后果句；任九一节写同一原因。
2. 离线测试：场序不同、停售时间不同各一例。
3. 离线测试：只有待核、没有冲突 → 展示与现在一致。
4. 离线测试：冲突解除 → 恢复展示单选、复式和任九。
5. 冲突说明里的队名、场序与核对结果里的字段逐字一致，不编造、不改写。
6. 合并后验收（Claude）：正式日报的 14 场一节照常。真实出现冲突的那一期再补验；出现之前只有离线测试，
   验收回执里照实写明。
