# T19 · 前瞻记分板与模拟投注账户

## 背景
T17 之后每天都会在开球前冻结一批预测，T18 回填历史后每日模型使用完整多赛季语料（`forecasts/<日期>/<run-id>/forecast.json`，含当时的竞彩 SP 快照）。
这是项目第一次拥有真正的「赛前预测 + 赛后结果」样本；在此之前所有评估都是历史回放。
所有者的目标是「准确的概率工具」与「作为投资的投注」两者结合。T15 的历史评估显示模型 LogLoss 比收盘赔率差 0.02–0.05，
而竞彩赔率内含约一成以上的抽水，因此「能否赚钱」目前没有证据。本任务只做两件事：
用真实比赛持续打分，以及用**虚拟资金**模拟几种下注策略并如实记录盈亏。真钱投注开关（BET）继续禁用，
报告不得出现任何购买建议措辞；是否开放真钱由所有者在门槛达成后另开任务单决定。

## 目标
1. 每天自动把已出结果的冻结预测与实际比分配对，累积逐场打分，生成按联赛、按模型版本的前瞻记分板。
2. 五个虚拟账户按固定规则模拟下注并逐注结算，输出资金曲线与统计，供所有者判断策略有无价值。
3. 给出两条明确门槛：「前瞻已验证」（概率质量）与「模拟盈利证据」（投注价值），都未达成前不改变任何对外标签。

## 范围
1. **配对与打分** `src/zucai/scoreboard/score.py`：
   - 输入：数据分支 `forecasts/` 下全部 `forecast.json` 与当天恢复出的数据库。只配对 `status=predicted`、
     赛果 `available_utc` **晚于** 该批 `generated_utc`、且常规时间比分完整的场次；同一场多批预测只取开球前最后一批。
   - 逐场记录：批次 ID、模型版本、联赛、P2 标签、模型三项概率、冻结 SP 去水概率、实际结果、模型 / 等概率 / 市场三列
     LogLoss 与 Brier。写 `scoreboard/scored.jsonl`（追加，幂等：同一场同一批不重复）。
   - 汇总：按联赛 × 模型版本、按月、总计；10 桶校准与平局偏差；写 `scoreboard/summary.json`。
2. **虚拟账户** `src/zucai/scoreboard/paper.py`，起始资金各 10000 虚拟币，每天对当批预测生成注单、对已结算场次结算：
   - **选注规则**（单场）：对每场的主胜 / 平 / 客胜三个选项计算 `ratio = 模型概率 × 冻结 SP`（`edge = ratio − 1`）；
     **`ratio` 严格大于门槛**才成为候选，每场最多选一个（取 ratio 最大）。门槛同时跑 **1.00 / 1.05 / 1.10** 三档
     （即 edge > 0.00 / 0.05 / 0.10；例如模型 48%、SP 2.5 时 ratio = 1.20，1.05 档入选），各自独立账户统计，
     报告默认展示 1.05 档，另两档在附表。门槛**不是**对 edge 本身比较：`edge > 1.05` 等价于 ratio > 2.05，
     真实赔率下几乎不会出现，会让账户永远不下注。
   - 账户 A **单场固定额**：每注 100。
   - 账户 B **单场分数凯利**：注额 = 资金 × 凯利比例 × 1/4，单注上限资金的 2%，下限 10。
   - 账户 C **热门对照组**：每场买三项中 SP 最低的选项，固定 100，不看模型；用来证明模型有没有超过「无脑买热门」。
   - 账户 D **二串一**：当日候选按 edge 降序取前两场（须为不同比赛）组一注，固定 100，奖金 = 100 × 两场 SP 乘积，全中才派奖。
   - 账户 E **三串一**：同上取前三场，固定 100。候选不足时当日不下注并记录原因。
   - 只用预测时冻结的 SP；注单在生成时写 `scoreboard/ledger.jsonl`（含批次、选项、SP、注额、规则、门槛），
     结算只更新同一行的结果与盈亏，绝不改注额与赔率。
   - 单关可售性：竞彩部分场次不开单关，模拟按「可单关」计算，README 与报告固定注明此偏差。
3. **记分板输出** `scoreboard/scoreboard.md`（数据分支，每天覆盖重写；历史由 git 保留）：
   - 顶部固定行：「非购买建议 · BET 禁用 · 虚拟资金模拟 · 竞彩含抽水」；
   - 概率质量：每联赛前瞻 n、模型 / 等概率 / 市场 LL 与 Brier、校准表、P2 标签、「前瞻已验证」标记；
   - 五账户各一行：注数、命中数、投入、回报、回报率、当前资金、最大回撤、最长连亏；1.05 档为主，附表给另两档；
   - 资金曲线用每周一个点的文本表（不引入绘图依赖）；
   - 稳健性：去掉回报最高的 5% 注单后回报率是否仍为正；bootstrap 1000 次的回报率 95% 区间（numpy 即可）。
4. **门槛**（写进 `scoreboard/summary.json` 与 README）：
   - 「前瞻已验证」：该联赛前瞻 n ≥ 200 且模型 LL ≤ 等概率 LL。未达成的联赛在 T06 报告里 P2 标签旁加「仅历史证据」。
   - 「模拟盈利证据」：账户 A（1.05 档）注数 ≥ 500、回报率 > 0、去掉前 5% 后仍 > 0、bootstrap 区间下限 > −2%。
     达成时只在记分板标「达到模拟门槛，待所有者决策」，**不改 BET，不改任何代码默认值**。
   - 漂移告警：连续 4 周前瞻平局偏差绝对值 > 5 个百分点，或任一联赛近 100 场 LL 高于等概率，记分板标黄并提示重跑 tune。
5. **工作流**：`football-feeds.yml` 的 `predict` job（T17）之后新增 job `scoreboard`，`needs: [predict]`，
   早班与晚班都跑（早班结算昨天，晚班结算当天已完赛并为新批次生成注单），`runs-on: ubuntu-latest`，
   复用 restore → 计算 → `publish-football-feeds.sh` 写回（`git add` 列表加 `scoreboard`）。Actions 摘要贴记分板前 60 行。
6. **Actions 摘要补比分前五**（`src/zucai/cloud_predict.py` `_summary`）：T17 摘要只贴了胜平负对照表，
   现在把 `report.md` 的「比分前五与快照」一节也贴进去，紧跟在每个北京日的比赛表之后；
   空批次时省略该节。只改摘要拼接，不改 `report.md` 的生成与冻结哈希；补一条离线测试断言摘要含比分行。
7. **测试**（离线）：合成 3 批预测 + 赛果 fixture，覆盖：只配对可知时间晚于生成时间的场次；同场多批取最后一批；
   幂等追加；五账户选注与结算（含串关全中 / 错一场 / 候选不足）；凯利上限与下限；三档门槛独立；
   稳健性统计可复现（固定随机种子）；门槛判定；漂移告警。
8. **文档**：README 新增「前瞻记分板与模拟账户」一节（含抽水说明、单关偏差、门槛、BET 仍禁用）；
   `docs/ARCHITECTURE.md` 模块表加 `scoreboard`，数据分支说明加 `scoreboard/` 三个文件。

## 不做
- 不开放真钱投注，不改 BET 开关，不输出「建议购买」类措辞，不做资金管理建议。
- 不改模型、不改 tune、不改 P2 门槛数值。
- 不抓新的数据源；串关只用冻结 SP 相乘，不模拟竞彩的奖金封顶与单关限制以外的规则。
- 不做图形界面；资金曲线用文本表。

## 验收标准
- 用 T17 已产生的真实冻结批次跑一次（若尚无完赛场次，用回放模式对最近 7 天批次打分），PR 描述给出：配对场数、
  各联赛前瞻 n 与三列 LL、五账户注数与回报率、数据分支提交号。
- 记分板顶部固定行与「单关偏差」说明存在；`summary.json` 的两条门槛字段均为 false（首次不可能达成）。
- `pytest -q` 全绿、`ruff check src tests examples` 与 `ruff format --check src tests` 通过；`reports/` 不新增内容。
