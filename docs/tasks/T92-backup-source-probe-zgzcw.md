# T92 备用来源探测：中国足彩网（zgzcw.com）

来源：所有者 2026-11-26：「把这个加入体彩赛事备选渠道：中国足彩网（zgzcw.com）」。
同一天所有者看过 T90 的探测结果后决定：「那就放弃新球体育，雷速体育的渠道补充」。

## 现状

- 14 场名单：主来源 500 网，备用澳客（T89）。
- 竞彩：只有竞彩网官方一个来源，在所有者的电脑上采集，没有备用。
- T90 的探测框架已经在用（`src/zucai/backup_source_probe.py`、`src/zucai/cloud_backup_source_probe.py`，
  探测种类 `backup-sources`）。第一次真实探测是运行 45763565563：新球体育没有可核实的访问规则，
  雷速体育的静态首页找不到赛程页，澳客的竞彩页静态正文里没有对阵。

## 范围

1. 候选名单里加入中国足彩网（zgzcw.com），探测它的 14 场对阵页和竞彩赛程页。
   具体网址由实现者从它的公开首页确认后写进 PR，审查时核对；确认不了的照实写「未确认」。
2. 候选名单里去掉新球体育和雷速体育（所有者已决定放弃）。澳客的竞彩页保留，作为对照。
3. 对中国足彩网回答与 T90 相同的四个问题，每个都要有证据：
   - robots.txt 写了什么，这两类页面的路径是否允许抓取，有没有访问时段或频率要求；
   - 页面是不是普通网页（不执行 JS 就能读到对阵和开球时间）；
   - 页面上有哪些字段：期号、场序、赛事、主客队、开球时间、停售时间、比赛编号；
   - 连续几次请求是否稳定。
4. 请求规则沿用 T90：只读 robots.txt 和最多 3 个公开页面，间隔不少于 3 秒，保存原始响应的哈希和裁剪后的样本。
5. 探测只在 GitHub Actions 里由 DeepSeek 触发（`operation=probe`，`probe_kind=backup-sources`），在所有者的采集机上运行。
6. 探测报告放 `reports/`（只放 `README.md` 和哈希清单，不超过 200 KB），结论写进 `docs/DATA_SOURCES.md`，
   并把 T90 的结果和所有者「放弃新球体育、雷速体育」的决定一并记入。

## 不做

- 不接入正式采集，不改日报。接不接，等报告出来由所有者决定，另写任务单。
- 不解析、不保存任何赔率或市场信息。
- 不上浏览器自动化，不绕过反爬、登录或验证码，不调用网站没有公开的接口。
- 开发环境不向这个网站发任何真实请求；离线测试只用仓库里的样本，样本只能来自 Actions 探测的产物。
- robots.txt 禁止的路径不请求。

## 验收标准

1. 离线测试：候选名单里有中国足彩网，没有新球体育和雷速体育。
2. 离线测试：T90 已有的分类测试（robots 禁止、返回非 200、页面需要 JS）对新候选同样成立；请求数和间隔的限制不变。
3. `tests/test_windows_collection_machine.py` 通过：探测程序在没有 Linux 专用模块时也能启动。
4. 合并后由 DeepSeek 触发一次真实探测，报告回填。Claude 核对报告的结论与原始证据一致后验收。
   这是探测任务，验收的是「问题有没有被证据回答」，不要求候选一定可用。
