# T54 竞彩缩写队名造成重复球队，阻断国家队映射

来源：2026-11-12 审查者在 T52 线上核对中发现。所有者确认开单。

## 现象与证据（数据分支 2026-11-12 状态）

- `state/teams.jsonl`：`[1149,"阿尔巴尼亚",["apif:欧国联:team:778"]]` 与 `[1156,"阿尔巴尼",[]]` 并存；
  1156 为 2026-11-12 竞彩开售采集时按四字缩写新建，无任何来源别名。
- `state/matches.jsonl`：`jc:2042694`（周四003，主队 1156、客队 1148）与 `apif:1528963`（主队 1149、客队 1148）
  同为欧国联、同开球 `2026-11-12T19:45:00Z`，却因主队编号不同被判为不同身份。
- 胜负彩 26163 期第 3 场（阿尔巴尼亚–芬兰）因此 `conflicting_identity`，全期 13/14 有概率；
  其余 5 场（土耳其、亚美尼亚、黑山、英格兰、捷克）缩写与库中名称一致，开售后正常映射。
- 同批新建、无别名的球队还有 1153（名为 `apif:team:4`，疑为占位名）、1154 布罗姆利、1155 伯顿、
  1157 巴恩斯利、1158 奥德汉姆、1159 谢周三、1160 阿克宁顿，需逐一核对是否为真实新队。

## 范围

- 以经核验的别名把 1156 并入 1149（或等价地让 `jc:2042694` 绑定 1149），保留合并审计记录；
  修复后 26163 期第 3 场应映射并有概率（若期次未截止）或在历史重放中映射。
- 竞彩采集新建球队前，先在**显式别名表**中查缩写→正式名；命中则复用，不命中才新建并写入
  `state/alias_candidates` 待人工核验。不得做前缀/模糊匹配自动合并。
- 排查并登记上述 7 支新队的来源与别名；`apif:team:4` 这类占位名须给出真实名称或标为待核。
- 在 DATA_SOURCES 记录竞彩队名缩写规则（四字截断）与别名表位置。

## 不做

不做模糊匹配；不改模型、参数、BET；不回写已冻结的预测、报告与账本；不使用正式 key 联网；
不批量重命名历史球队。

## 验收

1. 用 2026-11-12 数据分支快照离线重放：26163 期 14/14 映射，第 3 场 `match_id` 指向真实比赛且
   身份校验通过；其余 13 场 `match_id` 与概率逐字节不变。
2. 构造一个不在别名表中的新缩写队名：采集后不得自动并入任何既有球队，而是新建并进入
   `alias_candidates`。
3. 7 支待核球队各有登记结论（真实新队 / 别名并入 / 待核）。
4. 已冻结历史文件 SHA256 不变；全量 pytest、ruff 通过。
