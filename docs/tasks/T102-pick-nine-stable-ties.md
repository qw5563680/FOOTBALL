# T102 任九复式：并列时固定取法，同一天各班不再变来变去

来源：所有者 2026-11-27「写，两个都写」。

## 现状（main `aa0695d`）

- 任九复式（T87，`src/zucai/report/sfc.py` 的 `optimize_pick_nine`）在 64 注以内找「9 场全中」概率最大的方案。
- 任九是 14 场里任选 9 场。一场比赛「全包」（3 个结果都选）时这一场的覆盖是 100%，把全包放在哪一场都一样，于是最优方案有很多个并列的。
  程序在并列里没有固定取法，球队模型概率每班重新训练会有小数点后七八位的尾差，就足以让它换一个方案。
- 2026-11-27 的日报里，同一期（26172 期）六班之间全包的三场先后是：第 3、4、8 场 → 第 4、5、8 场 → 第 2、3、8 场 → 第 1、3、4 场。
  其中最后两种出自第 #299、#300 两班：这两班共有的球队模型概率最大只差一亿分之二点五，九场全中概率都是 8.01%，方案却不同。
  概率没有错，但看上去像推荐一直在变。

## 范围

1. **并列时按固定规则取。** 「9 场全中」概率相同（相对差不超过一亿分之一就算相同）的方案之间，依次按下面的顺序定：
   - 先选总注数少的（现有规则，保留）；
   - 全包优先放在球队模型最没把握的比赛上（最高一项概率最低的先全包）；双选同理，放在剩下最没把握的比赛上；
   - 还相同时取原场号小的。
2. **不受尾差影响。** 比较「有没有把握」时把概率取到小数点后六位再比。同一期各班之间，只要参与的场次和取到六位的概率没变，方案必须逐字相同。
3. 展示里加一句说明：全包放在最没把握的场次上；并列时按场号。
4. 14 场复式（`optimize_cover`）如果存在同样的并列，用同一套规则；不存在就不动，在 PR 里写明核对结果。
5. `docs/ARCHITECTURE.md` 同步。

## 不做

- 不改最优的标准：方案的「9 场全中」概率必须仍然是 64 注以内的最大值，不为了稳定而选更差的方案。
- 不改注数上限、可用场次的条件、任九单选、冻结与截止规则。
- 不用赔率或任何市场信息；BET 照旧禁用。
- 不改写已经冻结的旧报告和旧复盘。

## 验收标准

1. 离线测试：用 2026-11-27 这一期的概率（从正式归档裁剪成样本），给每个概率加上不超过千万分之一的随机尾差重复 50 次，方案逐字相同。
2. 离线测试：小样本穷举核对，方案的全中概率等于最优值；并列时全包落在最高一项概率最低的场次上，再并列取场号小的。
3. 离线测试：T87 原有的验收测试全部通过（上限 1 注时等于单选、不超过 64 注、不展示的三种情况）。
4. 离线测试：14 场复式的结果与改动前逐场相同，或 PR 写明哪里不同以及原因。
5. 合并后验收（Claude）：同一期连续两班正式日报，球队模型概率显示相同的情况下，任九复式逐字相同；全中概率与表内各场概率对得上。
