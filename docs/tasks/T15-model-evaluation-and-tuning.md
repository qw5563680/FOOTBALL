# T15 · 模型改进：多联赛多赛季评估、参数选择与无历史球队处理

## 背景
T08/T11 的回测只有英超 2026 年 9–10 月的 61 场：LogLoss 1.164（3h 重放）/ 1.296（默认），都高于等概率 1.099。
每折只有 7–10 场，折间 LogLoss 在 0.93–1.68 之间摆动，这个样本量说明不了模型好坏。
fd 已有 15 个已核验联赛、2122–2627 六季约 2.7 万场真实赛果，足够做稳定评估。
现状的三个明显短板：90 天半衰期是 T05 的占位值，从未验证；没有历史的球队（升班马）直接跳过；
没有一个"模型值不值得用"的判断标准。

## 目标
1. 建立可信的评估：按联赛、按赛季 walk-forward，评估样本以千计，每张表三列并排：模型 / 等概率 / 收盘赔率基准。
2. 用"前一赛季选参、下一赛季验证"选出每个联赛的半衰期，写进配置文件，训练与预测默认读取。
3. 无历史球队不再跳过，用保守先验并单独披露。
4. 给出每个联赛"能否启用 P2 预测"的判断；BET 一律仍禁用。

## 范围
1. **数据准备**（Codex 云端一次性完成）：用现有 `zucai fetch fd` 拉取 15 个已核验联赛 2122–2627 中存在的赛季 CSV，
   `--assume-known-after 3h`，请求间隔 ≥ 2 秒，不改采集代码。所有训练与评估只读这一份静态库，库文件 SHA256 写进报告。
   同时把当前数据分支恢复出来的 jc 赛果合入同一库（优先级 jc > fd，沿用 T08 去重）。
2. **评估器扩展**（`src/zucai/predict/backtest.py`、`zucai train`）：
   - 新参数 `--seasons 2425,2526`：按联赛赛季边界切（欧洲联赛 7 月起，JPN/SWE/NOR/FIN/USA/BRA 按自然年）；
     `--fold weekly|monthly`（网格搜索用 monthly 省时间，最终报告用 weekly）；
   - 每折训练用截点前的全部历史（跨赛季累积），评估该折；输出按赛季汇总和总计；
   - **收盘赔率基准**：读 `closing_odds`（bookmaker 优先 B365，其次 PS、Avg），去抽水归一化后只作对照列，
     模型与先验永不读取；报告里注明"收盘价是赛前最后报价，由出版方赛后发布，仅作参照上限"。
     T08 的"不消费 closing_odds"从本任务起放开为：仅允许回测对照列读取；
   - 跳过项分别计数：无历史球队、拟合失败；另给出 jc 对应场次子集（通过 `counterpart_id` 链接）的指标，样本小只作参考。
3. **参数选择**：新增 `zucai tune --league X --grid 90,180,270,365,540,730`：
   rolling-origin，用赛季 S 的 walk-forward 选出最优半衰期，再在赛季 S+1 上报告该值的成绩；
   至少覆盖 2425→2526 和 2526→2627 两个窗口；每个联赛给推荐值。
   结果写 `data/model/params.json`（按联赛：`half_life_days`、选择依据、评估窗口、生成时间）；
   `zucai train` 与 T06 预测默认读取该文件，命令行 `--half-life-days` 仍可覆盖并在元数据里标明来源。
4. **无历史球队**：`DixonColes` 增加先验：训练集中未出现的球队用该联赛攻防参数的保守收缩值
   （例如最弱四分位的均值；具体取法二选一并在报告说明理由），预测元数据加 `unknown_team_prior: true`；
   评估器把这类场次的指标单独成列，并给出开启先验前后（跳过 vs 先验）的总体对比。
5. **校准检查**：沿用 10 桶校准表，补"平局预测均值 vs 实际平局率"；若平局系统性偏差超过 3 个百分点，
   加一个只用训练折内数据拟合的单参数平局校正（不读任何赔率），报告里并列开/关两种结果；偏差不大就不加。
6. **报告** `reports/<日期>-t15-model-selection/README.md`（≤ 200 KB）：每个联赛一张表
   （赛季、评估 n、模型 LL/Brier、等概率、收盘赔率基准、无历史球队占比与指标），推荐参数，p2_ready 判断；
   全量评估 JSON 放工作目录，不进 main。
7. **启用门槛**（写进 README 评估一节与 `params.json`）：某联赛最近两个完整赛季 walk-forward 满足
   评估 n ≥ 500、模型 LogLoss 比等概率低 ≥ 0.05、且不比收盘赔率基准差超过 0.05，才标 `p2_ready: true`；
   T06 报告对未达标联赛继续显示"P2 实验"，达标联赛显示"P2 可用"；BET 与指标无关，继续禁用。
8. **测试**：赛季边界切分；rolling-origin 不泄漏（S+1 的数据不进入 S 的选参）；先验球队路径与披露字段；
   收盘赔率去抽水与缺失处理；`params.json` 读取、覆盖与来源标记；门槛判断。

## 计算预算
网格搜索用 monthly 折；最终每联赛 weekly 报告。总时长控制在几小时内，先跑英超/西甲/德甲/意甲/法甲/荷甲/英冠/葡超
八个联赛，其余七个联赛若时间允许再补，报告写明覆盖了哪些。

## 不做
- 不把赔率、收盘价或任何市场信息作为模型输入、先验或校准依据。
- 不改数据库 schema，不改采集、去重与可知时间规则。
- 不做 GBDT / 特征模型（T04 特征留给后续任务）。
- 不做定时自动训练（顺延为 T17；T16 为 T15 审查跟进）。
- 不启用 BET。

## 验收标准
- PR 描述给出：每个已覆盖联赛最近两季的三列指标表、推荐半衰期、无历史球队处理前后对比、校准结论、哪些联赛 p2_ready。
- 全部指标来自真实 fd/jc 数据，不接受合成数据替代；写明 fd 请求次数与间隔、库文件 SHA256。
- 测试全绿、ruff 通过；reports 目录只提交 README 与 SHA256SUMS。
