数据分支快照：`7ca04b3`（2026-11-04）；索引原件：T30 探测 Actions artifact 41779592141 的 21 页真实 `fixtures?league=&season=`（7 桥接联赛 × 2022/2024/2026）。
用 PR #50 的 `zucai stats link --raw-file` 对快照建索引时，被判「身份临时」的 fixture 共 2,113 条，全部因为下列 52 个 apif 球队 ID 没有正式别名。
每行一个来源 ID；「库内 fd 球队」是同联赛 ±3 小时窗口里、对手已由正式别名解析后，同一场 fd 比赛另一侧的球队在库内的现名，附证据场数，
属于同源场次共现证据，不是名称相似推断。建议规范名一律留空，由所有者逐行填写或确认「沿用库内名」；
只有所有者明确批准的行才能写入 `data/team_aliases/api_football.json`（status `approved`，带批准 PR 链接），不批准的行划掉。

## 为什么现在要批

七个桥接联赛的 apif 正式别名目前只覆盖参加过欧战的球队。T32 要按 apif fixture ID 回填逐场技术数据，没有正式别名的球队的比赛不能建索引，也就拿不到数据：
本批 21 页里 7,210 条 fixture 只建了 3,415 条索引。批完本清单后，2022、2024 两季可全部建索引；2026 季其余拒绝是尚未开球的比赛，正常。

## 填写说明

- 库内 fd 球队名是 football-data.co.uk 的英文原名（jc 没有卖过这些队的比赛，所以没有自动核验出中文短名）。核验结论只有两种：
  「沿用库内名」（规范名就写库内现名，比赛历史不受影响）或填一个中文规范名（会同时要求 T32 把 fd 别名改为同一规范名，合并同一球队）。
- 已核对库内这 63 支英文原名球队：除下文的 Den Haag 外，与 jc 球队没有分裂身份，所以沿用英文名不会影响模型的球队历史。
- 「无库内证据」的 7 行是该队在库内没有同窗 fd 比赛可对照（库内 fd 赛季范围或对手未解析），请只在确有把握时填写，否则留空继续 `proposed`。

- 多对一 14 条：法甲 / 葡超 / 西甲 最近一轮同一场比赛在库内同时有 `fd:` 与 `fdorg:` 两行，属于 T24 的 fd/fdorg 去重未完成，不是别名问题；T32 决定优先规则。
- 同窗冲突 9 条：荷甲 ADO Den Haag 的 apif 198 已有正式别名 → `海牙`（jc 名，库内 1 场），但 2026/27 季 fd 比赛（8 场）用的是 fd 原名 `Den Haag` 的另一球队行，
  同一俱乐部在库内分成两行。需要所有者单独确认一条 fd 别名：`Den Haag` → `海牙`（证据：apif 198 同源 ID、同窗 fd 对手一致）。确认后由 T32 实现者写入 `football_data_co_uk.json` 并合并两行历史；这是目前七个联赛里唯一一例 fd 与 jc 分裂的身份。
- 候选不全 1,659 条：1,638 条是 2026/27 季尚未开球的 fixture；其余 21 条是升降级附加赛与荷甲欧战附加赛，fd 季文件不含这些比赛，无需处理。
