# 策略提案：进攻/防守强度公开展示 + 一万次模拟算「多场合起来」的概率

日期：2026-11-19（北京时间）。提出人：所有者（2026-11-18 口述，参照 FiveThirtyEight 的 SPI 做法）；执笔与可行性检查：Claude。
状态：**待所有者决定**。本文件只是提案，没有改任何代码或数据。

所有者的原话：分别估算「进攻强度」和「防守强度」，再通过每场多达 10,000 次的蒙特卡洛模拟生成胜平负、晋级甚至实时滚球概率，
把这个功能加进模型预测，利用已有的数据。

## 先说结论（大白话）

| 所有者想要的 | 现状 | 建议 |
| --- | --- | --- |
| 分别估算进攻强度、防守强度 | **已经有了**。现在的球队模型每支球队就是一个进攻值、一个防守值，只是日报没有展示 | 做：在日报里把两个数直接列出来 |
| 一万次模拟算单场胜平负 | 现在用公式直接算，是精确值。改成模拟一万次，得到的是同一个数再加上约 ±0.5 个百分点的随机误差 | **不做**：不会更准，只会多一点噪声 |
| 一万次模拟算晋级 | 现在没有。两回合淘汰赛、加时、点球、联赛阶段排名，这些公式很难写，模拟正合适 | 做：这是模拟真正有用的地方 |
| 一万次模拟算胜负彩 14 场「中几场」 | 现在只有「全中」的概率 | 做：顺带得到中 14、13、12……场各自的概率 |
| 实时滚球概率 | 没有。需要每分钟的比分、红牌数据和每分钟运行一次的程序；竞彩也不卖滚球 | **本提案不做**，原因见第 8 节 |

一句话：模拟不会让单场预测更准；它的用处是把很多场比赛**合起来**算的事情（晋级、排名、中几场）。

## 1. 一句话假设

用已经冻结的每场比分概率做 10,000 次模拟，得到的「晋级概率」「联赛阶段出线概率」是校准的
（说 70% 的事，大约 70% 会发生），并且比不看球队强弱的朴素猜法更准。

单场胜平负不在假设里：模拟结果必须与现有公式结果一致（差距只来自抽样），这一条是验收项，不是要验证的假设。

## 2. 用什么数据

- 只用仓库已有的东西，不新增数据来源：
  - 每场比赛已冻结的比分概率表（现行 Dixon-Coles 球队模型的输出，含每队进攻值、防守值、主场优势）；
  - 库内已有的赛程与赛果（欧冠、欧联、欧协联、欧国联的对阵和比分），用来确定谁对谁、当前积分；
  - 胜负彩期次与场次对应关系（已有）。
- 「赛前何时可知」：模拟只读某个截点**已经冻结**的预测批次，不重新训练；截点之后的赛果不进入该次模拟。
  每次模拟记录所用批次的哈希、随机种子和次数，同样的输入必须得到同样的结果。
- 缺一样数据：库里的赛果只存 90 分钟比分和半场比分，**不存加时和点球的结果**。要给「晋级」记分，必须知道最后谁晋级。
  接口的原始返回里有这两个字段，但没有入库。这需要加一个字段（见第 6 节），并且先由审查者经 Actions 探测拿到真实样本再接入。
- 红线自查：
  - 不用赔率、收盘价或任何市场信息作输入、先验、校准或选参。模拟的输入只有球队模型的冻结概率。
  - 不用赛后才知道的信息。
  - 不改球队模型本身；模拟只是在它的输出上做加工，不回流。

## 3. 怎么验证

分三层，前一层不过，后一层不做。

1. **一致性（验收项，离线）**：对同一场比赛，10,000 次模拟得到的胜平负、比分、总进球、半全场概率，
   与公式结果的差都在抽样误差之内（例如胜平负各项差不超过 1.5 个百分点）；固定种子重复运行结果逐字相同。
2. **历史回放（描述性，不算证明）**：对库内已有的欧战淘汰赛两回合对阵，用当时截点的模型概率回放晋级概率，
   与实际晋级结果比 Brier 分和校准。回放数字只作描述，不据此声称有效。
3. **前瞻（真正算数的）**：从合并之日起，每个淘汰赛对阵在首回合开赛前冻结一次晋级概率，赛后记分。
   对比两条朴素基线：一律 50%；以及「联赛阶段排名靠前的一方 60%」。指标：Brier、Log Loss、校准。
   联赛阶段出线概率（前 8、前 24）同样冻结记分，但同一赛季的这些事件彼此相关，样本数按「赛季 × 赛事」保守计。

胜负彩「中几场」的分布只作展示和事后对照，不另设假设。

## 4. 要多少样本、多久

- 欧冠、欧联、欧协联每个赛季各约 23 个淘汰赛对阵（附加赛 8、十六强 8、八强 4、四强 2、决赛 1），三项合计约 69 个。
- 本赛季联赛阶段到 2027 年 1 月结束，淘汰赛 2 月到 5 月。也就是说，**到 2027 年 5 月大约能攒到 60 多个前瞻样本**。
- 这个样本量只够看出明显的不校准，不够证明「比基线好一点点」。提案如实写明这一点，不承诺在一个赛季内得出强结论。

## 5. 失败标准

出现下面任何一条就关掉晋级模拟这条输出：

1. 一致性验收不过（模拟与公式对不上），不上线。
2. 攒满 60 个前瞻淘汰赛样本后，Brier 分不比「一律 50%」好。
3. 攒满 60 个样本后，按预测概率分三档，任何一档的实际发生率与预测均值相差超过 15 个百分点。
4. 任何一次发现模拟用到了截点之后的赛果或任何市场信息，立即停用并复盘。

进攻/防守值的展示和胜负彩「中几场」分布不设采用门槛（它们不改变任何预测），但如果日报因此变得更难读，所有者说停就停。

| 项目 | 成本 |
| --- | --- |
| 新增 API 请求 | 0（模拟只读已有数据）。加时/点球字段若要历史回填，需审查者先做一次探测，请求数另报所有者 |
| 新增数据表/字段 | 赛果需增加「加时比分、点球比分或晋级方」字段；另加一张模拟结果冻结表。两者都要同步更新 `docs/ARCHITECTURE.md` |
| 计算量 | 每场 10,000 次抽样是毫秒级；整届杯赛模拟到决赛约数秒。每日运行时间增加可忽略 |
| 依赖 | 只用已有的 `numpy`，不引入新依赖 |
| 日报改动 | 预测表后加一行「主队进攻/防守、客队进攻/防守」；欧战比赛日加一张「晋级概率」小表；胜负彩一节加一行「中几场」分布 |
| 记分板改动 | 新增「晋级预测」一栏，单独统计，不进虚拟账户、不进纸面串关 |

## 7. 与现有实验线的关系

- 当前的模型实验线：`dc-sot-v1`（射正）与 `dc-xg-v1`（预期进球）每天在跑（2026-11-19 日报的实验模型表里只有这两条）；
  T64 的全数据模型与 T72 的「球队＋市场（实验）」已立项，是否已在每日并行输出以日报为准。上限四条。
- **本提案不占实验线名额**：它不产生新的单场胜平负概率，不与正式模型比谁更准，只是把正式模型的输出加工成「多场合起来」的概率。
  性质上与 T45 的纸面串关层相同。
- 成绩单独记，不进虚拟账户与纸面串关，不适用转正规程；BET 保持禁用。

## 8. 为什么本提案不做实时滚球

1. **竞彩不卖滚球。** 竞彩的胜平负、让球、比分、总进球、半全场都在开赛前停售，赛中概率在本项目里没有可以对照的玩法。
2. **缺数据通道。** 滚球概率要每分钟的比分、红牌、换人。现有套餐是否包含实时接口、配额够不够，没有核实过；
   按规定要先由审查者探测，不能假设。
3. **缺运行方式。** 现在每天定时跑三班。滚球要比赛期间每一两分钟跑一次，GitHub Actions 的定时任务做不到这么密，也不稳定；
   这需要一台常开的机器，属于新增基础设施。
4. **验证难。** 赛中概率没有市场对照（红线不允许拿赔率进模型，本项目也不采集赛中赔率），只能事后看校准，样本积累很慢。

如果所有者仍然想要，建议作为单独的提案，先回答第 2、3 两点的成本，再决定。

## 9. 建议的分步做法（每一步都可以单独停）

1. **展示进攻/防守值**（最小的一步，不涉及模拟）：日报预测表里列出两队的进攻值、防守值，并用一句话解释怎么读。
2. **模拟引擎 + 一致性验收**：只做引擎和离线测试，不改日报。
3. **胜负彩「中几场」分布**：在胜负彩一节加一行。
4. **晋级概率**：先补加时/点球赛果字段（需探测），再做两回合淘汰赛与联赛阶段出线的模拟、冻结和记分。

## Claude 的可行性与红线检查

- 可行：1、2、3 步只用已有数据和依赖，改动面小。第 4 步依赖一个新字段和一次探测，工作量最大。
- 红线：提案全程不使用市场信息，不改球队模型，不用截点后的数据；与 AGENTS.md「市场信息的使用」不冲突。
- 需要所有者知道的三点：
  1. 单场预测不会因为模拟变准。如果目的是「预测更准」，这份提案帮不上；该走的是现有实验线（射正、预期进球、全数据）。
  2. 晋级概率的质量取决于欧战模型本身。欧战目前是合并模型，前瞻样本只有十几场，证据不足；模拟会原样继承它的误差。
  3. 一个赛季只有 60 多个淘汰赛样本，结论会来得很慢。
- 建议：先做第 1 步和第 2 步（成本低、立刻能看到东西），第 3、4 步看过效果再定。
