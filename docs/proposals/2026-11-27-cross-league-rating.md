# 策略提案：跨联赛的球队评分（第四条实验线）

日期：2026-11-27（北京时间）。提出：所有者 2026-11-27「乙、丙都写」里的丙，要求从此前给过的知名预测模型清单里挑一个方向做实验；
执笔与可行性检查：Claude。状态：**待所有者看过后决定是否开工**，任务单见 `docs/tasks/T100-cross-league-rating-experiment.md`。

## 先说结论（大白话）

- 现在的正式球队模型是**每个联赛单独算**的。一支球队刚升级、刚降级，或者在杯赛里碰到别的联赛的球队，
  模型在这个联赛里对它几乎没有记录，只能用「按本联赛最弱四分之一的球队打个折」来代替（`weakest_quartile_half_shrinkage`）。
- 清单里的 Elo 评分和 FiveThirtyEight 的 SPI 有一个共同点：**一支球队只有一个分数，走到哪个联赛都带着**。
  本提案就试这一点：给每支球队算一个跨联赛、跨赛季连续更新的评分，只用比赛结果，再把两队的分差换成胜平负概率。
- 老实话：这类评分模型在同一个联赛内部，通常不比现在的模型准，多半是差不多或略差。
  它可能有用的地方是「新面孔」比赛，以及作为一个做法完全不同的第二意见。所以失败标准写得比较严，不行就关，把实验位让出来。
- 不用赔率，不用任何市场信息，不新增数据来源，不新增接口请求。

清单里其余几项为什么这次不选：

| 清单里的模型 | 这次不选的原因 |
| --- | --- |
| xG（预期进球） | 已经有一条实验线在跑（`dc-xg-v1`） |
| Opta 超级计算机 | 核心是「模拟一万次算赛季结局」，这部分已由 T77 做了；它的单场概率还混入了市场赔率，球队模型不能用 |
| FiveThirtyEight SPI | 完整做法要球员身价等外部数据，项目里没有。本提案取它「强度跨联赛通用」这一点 |
| Maher 泊松、Dixon–Coles | 就是现在的正式模型 |
| 贝叶斯分层模型 | 计算重、调参多，留作以后的候选 |

## 1. 一句话假设

给每支球队一个跨联赛、跨赛季连续更新的评分（只用赛果），由它得到的胜平负概率，
在同一批冻结的比赛上不比现行正式模型差；在「球队在本联赛历史很少」的比赛上比正式模型好。

## 2. 用什么数据

- 只用库里已有的比赛结果：比赛时间、主客队、90 分钟比分、所属赛事。来源就是正式模型现在用的那几个（`jc`、`fd`、`fdorg`、`apif`），不新增。
- 球队身份用库里现有的球队表。一支球队在不同联赛是不是同一行，决定了评分能不能「带着走」。
  已知有缺口：身份合并审计里有 17 行「目标联赛正式别名未传播」（德乙 8、荷乙 9），这些球队在次级联赛的历史还挂在临时身份下。
  任务单第一步先把这类缺口数清楚；补齐属于队名批准（Claude 备证据、所有者批准），不在实验里绕过。
- 「赛前何时可知」：评分只用截点之前已经可知的赛果，判断规则沿用正式模型现有的那一套；历史赛果是回填的，
  与现有两条实验线一样标 `backfill_replay`，目标比赛按真实采集时间严格冻结。
- 红线自查：
  - 不用赔率、收盘价或任何市场信息作输入、先验、校准或选参。参数只在赛果上选。
  - 不用截点之后的信息。选参只用 2026-07-01 之前开赛的比赛；之后的比赛只用来验证，不回头改参数。
  - 不改正式模型，输出不回流。

## 3. 怎么验证

1. **先登记，后回溯。** 实现者先把评分公式、候选参数、选参办法、评估口径写成协议文件并记下哈希，再跑第一次回溯；
   跑失败了也要在 PR 上登记（沿用 T72 的做法）。
2. **回溯（描述性，决定要不要上线）。** 用 2026-07-01 之前的比赛选定参数后冻结；在 2026-07-01 之后已有赛果的比赛上，
   与正式模型的历史回放按比赛编号逐场配对，比 Log Loss、Brier 和校准。
3. **前瞻（真正算数的）。** 合并后作为第四条并行实验线，和正式模型同批、同场、同截点冻结，赛后记分。
   主指标 Log Loss，对手是正式模型（`dixon-coles`）。
   - 评估口径在开工前定死：**所有联赛合并成一组**算共同样本，另按联赛列出描述性数字。
     现有两条实验线按联赛分组，一个月下来每组只有 0 到 10 场，离 200 场太远；这条线不分组，约一个月能到 200 场。
   - 另列一个子样本：正式模型对至少一队用了「默认强度」（上面说的打折办法）的比赛。这是假设的后半句。
   - 成绩单上再加一行对照：正式模型与评分模型各占一半的平均。它只在赛后计分时算，不发布、不进日报、不占实验位。
     用来回答「两个做法不同的模型合起来看是不是更准」。
4. 采用门槛沿用现有规则（`t34a-adoption-v1`）：共同样本 ≥ 200、覆盖率 ≥ 90%、Log Loss 差为负且 95% 区间上界为负、校准不变差。
   达到门槛只是「提交所有者决定」，不自动替换任何东西。

## 4. 要多少样本、多久

- 正式模型从 2026-11-02 到 11-26 有 242 场比赛记了分，平均每周约 60 场。
- 合并成一组计算，约四周能到 200 场共同样本，约五周到 300 场。国家队比赛窗口和冬歇期会让它忽快忽慢。
- 「默认强度」子样本少得多，预计每月十几到几十场，结论要等更久；提案不承诺它在一个季度内有结论。

## 5. 失败标准

出现任何一条就关掉这条线，把实验位让出来：

1. 回溯阶段：验证段上，评分模型的 Log Loss 比正式模型同场高出 0.015 以上。直接不上线，不占实验位。
2. 前瞻满 300 场共同样本：Log Loss 差（评分模型减正式模型）的 95% 区间下界大于 0，也就是明确更差。
3. 前瞻满 600 场共同样本仍未达到采用门槛，并且「各占一半的平均」也没有胜过正式模型（95% 区间上界不为负）。
4. 任何一次发现用到了市场信息或截点之后的数据：立即停用并复盘。

## 7. 与现有实验线的关系

- 现在在跑三条：`dc-sot-v1`（射正）、`dc-xg-v1`（预期进球）、`team-market-blend-v1`（球队＋市场）。上限四条，本提案用掉最后一个空位。
- 和前两条不重复：它们是在正式模型里加技术统计，仍然每个联赛单独算；这条换的是「球队强度怎么表示」。
- 和融合线互不相干：融合线用市场信息，本线不用；本线的输出不进融合线。
- 和乙（T62，给没有模型的赛事补模型）的关系：评分天然能给任何两支有评分的球队出概率，包括国内杯赛。
  本提案**不**拿它去填那些赛事；只在回溯报告里顺带数一数这类比赛有多少场两队都有评分，供以后决定。
