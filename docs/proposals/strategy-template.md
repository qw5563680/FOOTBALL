# 策略提案模板（独立复核员 / 任何人提出新策略时使用）

每份提案一个文件：`docs/proposals/<日期>-<短名>.md`，由所有者转交 Claude 做可行性与红线检查。
写不出「失败标准」的提案不进入任务单。

## 1. 一句话假设
要验证的因果或相关关系是什么（例：「赛前 24 小时内主力缺阵 ≥2 人的球队被市场低估」）。

## 2. 用什么数据
- 来源与字段（必须是仓库已有或 `docs/DATA_SOURCES.md` 允许接入的来源）。
- 每条数据「赛前何时可知」怎么确定；回填数据与真实捕获数据如何区分。
- 红线自查：是否用到赔率或收盘价作为球队模型输入？是否用到赛后才知道的信息？

## 3. 怎么验证
- 与哪个正式模型比、在哪些联赛、用什么指标（LogLoss / Brier / 校准 / 覆盖率 / 纸面 ROI）。
- 冻结前瞻样本如何产生（并行实验模型、同场同批次）。

## 4. 要多少样本、多久
- 达到结论所需的共同样本数与预计日历时间（按当前每周场次估算）。

## 5. 失败标准
- 出现什么结果就关掉这条线（例：200 场共同样本后 LogLoss 差 95% 区间上界 ≥ 0）。

## 6. 成本
- 新增 API 请求 / 配额、新增数据表、对日报与记分板的改动。

## 7. 与现有实验线的关系
- 当前并行实验线（最多三条）各自状态；本提案替换哪一条，或为何可以并行。
